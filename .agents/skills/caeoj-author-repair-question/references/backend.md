# 可信源码构建与实际验证

用于评估当前源码修复后端能否承载新题，以及验证必要适配。权威配置与消费逻辑以代码为准，不从首题复制一个逐题 verifier。

## 复用入口与能力边界

- [源码修复装配](../../../../src/caeoj_tools/source_repair.py)：读取题内 `harbor/source-repair.json`，检查声明并生成环境及 Oracle 绑定。
- [逐次构建执行](../../../../src/utils/harbor/tests/source_repair.py)：冻结提交、可信基线及候选编译、产物冻结、可信运行入口。
- [任务装配](../../../../src/utils/prepare_harbor.py)和[公开包](../../../../src/utils/publish_dist.py)：选择后端、装配评分／数据、公开材料白名单。
- [回归用例](../../../../tests/test_harbor.py)及[Chrono 后端探针](../../../../qbank/19-solver-repair/19.1-constraints/constrained-assembly-repair/author/backend_probe.py)：复用可适用的测试思想；具体路径与缺陷注入按新题调整。

当前配置面向 Linux CMake 可信目标、限定 C/C++／Fortran／Python 源文件替换及可信 runner；支持后缀只表示可接收文件，不能据此宣称该语言环境已经验证。Python题可由固定CMake目标进行语法／字节码构建，须删除并重建实际导入使用的pyc，冻结实际源码和缓存，并验证解释器cache_tag和模块路径。它不是补丁脚本或任意构建系统的通用服务。声明不能表达新需求时，先按职责补充共享能力并验证旧通路，不靠私有字段或逐题脚本绕过限制。当前公开包也不支持将源码修复题与其他题静默拼成普通多题包。

## 提交与构建链

公开说明可修改的文件、目标映射、API 义务、大小及资源限制。判题只接收符合声明的普通文件；拒绝额外文件、符号链接和越界路径；冻结后的源文件才是实际评分对象。开发环境中的二进制、构建缓存及驱动改动不能成为判题输入。

运行可信原件构建时，也要强制重建相关 object／库。仅执行 `cmake --build` 可能因缓存无事可做，无法证明编译器仍可用；这种情况下直接把后续候选编译失败记零分会误判基础设施故障。保存原件构建日志，再替换源文件并再次删除声明产物、编译候选，记录实际源码与产物哈希。

候选编译成功不证明驱动加载了该库。验证实际动态链接路径及一次真实输出判分，并检查未来时间戳等缓存条件不能绕过重建。构建后冻结源码、库、驱动及提交，候选运行 UID 不应改写可信路径。允许修改头文件时，按真实编译依赖确定所有受影响的翻译单元，强制重建其对象并重新链接；只重编一个直接实现文件不足以证明头文件修复完整生效。检查文件及父目录的写权限，包含头文件、构建规则、解释器配置和动态导入路径。

原件可信构建失败属于基础设施错误；有效候选的语法错误或编译超时属于候选失败。分类应由实际执行证据支持，而非单看某个命令的非零退出码。总 verifier 预算需覆盖原件重建、候选编译、全部 case 与评价开销，逐项检查真实消费者。

语法构建不执行依赖导入，Python等题应配置可信`baseline_probe`命令，在替换候选之前以运行UID真实导入并调用驱动的非触发状态；失败归基础设施。该命令仅由维护配置提供，使用参数数组且不经shell，不来自提交或输入。记录命令、退出状态与日志；不能把空状态循环或py_compile当成真实子模型调用。旧库与公开SDK的依赖约束冲突时，可使用分离解释器并以明确协议传递数据；分别验证两套真实依赖、实际导入文件和缓存、错误传播及超时对子进程的清理。探针必须使用判题的运行UID、HOME和环境，先排除探针自身的路径或环境错误，再归因于正式运行时。

## 可信运行与公开包

驱动负责读取、构造真实系统、调用规定 API、输出观测量；数据 adapter 负责协议转换。检查参考是否在同一观测定义下生成，特别是力的端点、符号、局部／全局坐标以及状态写回。

将底层进程失败的 stderr、退出码及超时信息保留到可诊断的作者日志；外层 Python 的 `CalledProcessError` 往往遮住真正原因。日志仍需遵守公开／私有隔离与输出大小限制。缺少底层 stderr 时如实限制归因，不推断精确抛出位置。

公开资产用显式白名单及哈希绑定，保留必要源码与许可；版本控制也须保留被绑定文件的原始字节，检查Git暂存内容或新检出目录的SHA，不能只校验当前工作树。换行转换可能在提交时改变已验证资产而不改变其表面代码；对这些冻结材料使用适当的字节保留规则，不通过修改哈希掩盖内容差异。维护者修复文件、隐藏参考、作者计算脚本不得进入考生包或镜像。独立解包安装并从公开说明运行样例，检查镜像是否具备真实运行时依赖；Python 可导入不等于其动态库依赖齐备。源码闭包删去大资产时核对仍能构建及执行，不把完整仓库下载成功当作公开包可用。

## 有意义的实际探针

根据改动风险选择探针，不要求每题机械重做相同数量。复用结果需匹配当前后端／镜像内容及配置，说明覆盖：

| 情境 | 要验证的行为 |
|---|---|
| 有效修复、陈旧或未来时间戳缓存 | 实际强制编译，驱动加载新库，真实 case 能判分 |
| 候选语法错误／编译超时 | 候选失败，编译子进程组清理 |
| 可信编译器或构建文件缺失，缓存原本完整 | 实际原件重建发现基础设施错误 |
| 额外文件、符号链接、超限文件 | 提交冻结前拒绝，未混入可信执行路径 |
| 求解超时 | 独立逐例预算及子进程清理，后续 case 可完成 |
| 当前低权限用户、隐藏目录和冻结产物 | 不能读私有材料、不能写可信产物，网络及 CPU／内存限制实际生效 |
| 共用框架改变 | 普通 solve.py 的冻结／执行／评分仍可实际走通 |

有限路径的权限探针不是整个容器安全性证明，`ldd` 与单次执行也不证明所有动态加载场景；报告实际范围。独立后端审阅检查公开要求到消费者的映射、错误归因与探针证据，结构检查或编译通过不能替代数值参考验证。
