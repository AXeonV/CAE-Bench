# CAE 章节出题

读取仓库根目录下 `qbank/PHILOSOPHY.md`、目标章／节规划及 [出题工作流](../../../qbank/design/AUTHORING.md)，按该工作流完成用户指定阶段。不要将 2.1 的物理范围、材料集合、目录 slug、阈值或资源上限机械复制到其他领域。

先记录目标编号、题目清单、交付阶段、数据是否在范围内、已有用户改动和依赖协议。未要求生成数据时，默认完成题面阶段；保留已有数据，不为占位伪造样例或标答。不把“自动化工作流”解释为定时任务，也不自动开始其他章节。

工作顺序：规划映射 → 协议缺口分析 → 公共要求／逐题撰写 → 静态检查 → 独立考生审阅 → 修订与复核 → 维护记录及交付。发现协议缺口时，先完成不依赖缺口的工作；必要扩展同步规范、Schema、校验器、SDK 及相关验证，避免以自然语言承诺不存在的表达能力。牵涉用户未授权的新物理范围或发布行为时，明确待决事项。

独立审阅是本技能流程的一部分：使用单独 subagent，仅给考生可见材料与真实任务，不给作者预设答案或期望结论；明确只读且不能借隐藏数据、实现代码或维护记录补足题意。修订后对最终版本复核；没有独立审阅能力时如实标为“未完成独立审阅”，继续完成可执行工作，不以作者自审冒充。

运行脚本检查现有题面（不写输入数据、不执行题目代码）：

```sh
python .agents/skills/caeoj-author-section/scripts/check_statements.py \
  --section qbank/<chapter>/<section> \
  --output runs/authoring/<section>/static.json
```

脚本仅识别节目录直接子目录中的 `instruction.md`／`DATA.md`，检查该节 Markdown 中的常规内联文件链接和 JSON 代码块。题目数量与规划的语义对应、物理和协议正确性仍由 Agent 核查。采用其他布局时调整入口或脚本，不为通过检查改坏既有结构。

涉及已有实际数据时结合 `caeoj-audit-data` 技能核查全部输入输出；其 inventory 当前只自动发现 `cases/*/problem.json` 与 `samples/*/input/problem.json`，qbank 的 `examples` 须另行遍历，不能遗漏后声称完整审计。数据缺失不阻止题面交付，但不能声明已完成数据验证或正式发布。

维护方审阅记录按工作流保留已发现问题、修订及剩余限制。检查 diff，按用户的提交偏好提交本次文件；不纳入无关改动。最终分别报告题面、独立审阅、数据和评测发布状态，不以测试数代替物理或参考准确性证据。
