# CAE 章节出题

读取仓库根目录下 `qbank/PHILOSOPHY.md`、`qbank/design/README.md`、已有的目标章／节规划及 [出题工作流](../../../qbank/design/AUTHORING.md)，同时读取 [经验清单](../../../qbank/design/AUTHORING-LESSONS.md)，按该工作流完成用户指定阶段。规划不存在或只有方向时，先补齐，不将缺少规划当作出题的阻塞条件。不要将 2.1 的物理范围、材料集合、目录 slug、阈值或资源上限机械复制到其他领域。

先记录目标编号、现有规划的清晰程度、交付阶段、数据是否在范围内、已有用户改动和依赖协议。按“总体章目录 → 章内各节 → 目标节的逐题清单”自上而下补足依赖：例如第三章未规划而用户要求 3.1，先提出并保存第三章各节规划，再细化 3.1；2.3 只有方向时先将其拆为明确题目。章级只需确定各节范围、相邻边界及后续方向，不展开无关节的全部题面。保留已有编号和决定，给新增选择记录依据。

将规划写入 `qbank/design/` 并更新目录。规划先于题面；先提出可审查的具体方案，再按用户要求继续：仅请求规划则止于规划，请求完成出题则对符合已定原则的常规选择自主推进，不默认增加逐级批准环节。只有冲突于已有决定或无法合理判定的关键目标才提出具体选项澄清，同时推进独立工作。未要求生成数据时，完成到题面阶段；保留已有数据，不为占位伪造样例或标答。不把“自动化工作流”解释为定时任务，也不因补足上级规划而实施其他节。

工作顺序：规划盘点与逐级补全 → 目标节逐题定义 → 协议缺口分析 → 公共要求／逐题撰写 → 静态检查 → 独立考生审阅 → 修订与复核 → 维护记录及交付。逐题定义须明确能力范围、维度、分析／统计目标、材料、方法责任、共同观测及与相邻题目的区别；不能以几何、来源或模型名称填满清单。发现协议缺口时，先完成不依赖缺口的工作；确需设计或修订协议时使用 [caeoj-extend-io](../caeoj-extend-io/SKILL.md)，完成缺口、兼容性与实现验证后回到出题流程，避免以自然语言承诺不存在的表达能力。牵涉用户未授权的新物理范围或发布行为时，明确待决事项。

整章任务先形成覆盖全部目标节的有限逐题清单，再按节或协议依赖分批实施。维护逐节状态表，记录规划、题面、协议实现、静态检查、独立审阅、未决项及下一步；已有完成项只核查和必要修订，不从头重做。中断／续作先读取记录并核对实际文件，不把一次上下文或一次回复当作整章范围。共享协议或公共文档改变后重查所有受影响题目的验证与审阅状态，最后做章内覆盖、编号、跨节重复和公共语义一致性核查。不得仅因题目很多、协议尚未存在或数据暂缺而将目标节静默删去或只留下 TODO；未完成项如实保留，继续推进其他可完成项。

独立审阅是本技能流程的一部分：使用单独 subagent，仅给考生可见材料与真实任务，不给作者预设答案或期望结论；明确只读且不能借隐藏数据、实现代码或维护记录补足题意。修订后对最终版本复核；没有独立审阅能力时如实标为“未完成独立审阅”，继续完成可执行工作，不以作者自审冒充。

运行脚本检查现有题面（不写输入数据、不执行题目代码）：

```sh
python .agents/skills/caeoj-author-section/scripts/check_statements.py \
  --section qbank/<chapter>/<section> \
  --output runs/authoring/<section>/static.json
```

仅规划阶段不运行该脚本。脚本仅识别节目录直接子目录中的 `instruction.md`／`DATA.md`，检查该节 Markdown 中的常规内联文件链接和 JSON 代码块。题目数量与规划的语义对应、物理和协议正确性仍由 Agent 核查。采用其他布局时调整入口或脚本，不为通过检查改坏既有结构。

涉及已有实际数据时结合 `caeoj-audit-data` 技能核查全部输入输出；其 inventory 当前只自动发现 `cases/*/problem.json` 与 `samples/*/input/problem.json`，qbank 的 `examples` 须另行遍历，不能遗漏后声称完整审计。数据缺失不阻止题面交付，但不能声明已完成数据验证或正式发布。

维护方审阅记录按工作流保留新增规划及依据、已发现问题、修订及剩余限制。检查 diff，按用户的提交偏好提交本次文件；不纳入无关改动。最终分别报告规划、题面、独立审阅、数据和评测发布状态，不以测试数代替物理或参考准确性证据。
