# 配置映射与验证

任务边界及独立审阅条件见 [SKILL](../SKILL.md)。配置语义以[评测维护说明](../../../../qbank/maintenance/EVALUATION.md)和[评分说明](../../../../docs/GRADING.md)为唯一维护位置，本页只说明如何建立证据。

## 要求到生效项

从 instruction 与 DATA 提取输出及单位、误差尺度、偏置、聚合、逐例／总分、程序入口、依赖和资源；用实际数据确认逻辑字段及实例数。记录：

| 要求 | 需要证明 |
|---|---|
| 字段策略及聚合 | 每个实际输出被正确绑定，公开公式、单位、权重及偏置与引擎等价 |
| 逐例及总成绩 | 混合通过／失败、部分完成及基础设施错误的含义与题面一致 |
| 运行限额 | 配置来源、合并值、单位及实际限制器的作用域 |
| 外层预算 | Agent、构建、逐例求解和总 verifier 分开计算，包含必要 I/O 与判分开销 |
| 运行材料 | 公开包、题目绑定、策略和 verifier 使用一致的装配，隐藏材料隔离 |

区分“能解析”“被采用”“实际执行”。查解析器、消费者和模板，不添加无人读取的配置键。继承满足要求时无需逐题写覆盖文件。

case配置在reference/grading.json完整声明评价及数值策略；作者模板不被运行器读取。内层数值策略按当前支持形式选择，固定逻辑名与 quantity／unit 绑定的规则见评分说明；不能把 quantity 当输出对象名。reference_offset 只能应用公开规定的误差尺度，不改变物理值或由答案拟合。case配置或参考缺失、评价项漏绑及重复容差来源均在solver前处理。

无数据时完成可确定映射并记录待绑定项；临时 fixture 不证明真实实例覆盖。缺题意要求反馈出题，字段不清反馈 DATA，数据冲突反馈审计。普通适配自主推进；判据意义、模型责任或资源承诺变化须先处理公开要求。

## 有区分力的验证

按变更风险选择，不为纯措辞运行高成本模型：

- 配置实际加载与所有输出覆盖；缺策略、未知／冲突配置须按约定失败。
- 已知正确／错误输出、阈值等号及两侧、聚合与偏置；结构错误不能被数值策略放过。
- 非零退出、缺输出、超时、非法／超大输出；坏输入／参考／配置归基础设施错误，不计考生零分或未运行案例失败。
- 最终分数、分母、逐例覆盖及部分完成状态。
- CPU、线程、内存、输出大小和各层时间预算的实际消费；静态值不能证明容器限额生效。
- 装配或框架变化时验证真实组装、策略／实现绑定和候选／verifier 边界；不足时报告缺口，不用假正式数据绕过前置。

公开包在自身根目录普通安装，移出源码目录核对 CLI、SDK、资源与扩展；可复用 `qbank/maintenance/authoring/verify_install.py --domain <领域>`。开发 editable 安装与 ZIP 前暂存检查不能替代独立安装。缺扩展不得退回通用检查，维护命令不进入考生命令。

CLI 退出与错误分类按当前 CONTRACT／评分说明核对，相关源码见[定位索引](current-backend.md)。重大适配由独立 subagent 检查需求映射与测试证据；这项审阅不代替实际执行。

## 交付

交付配置、必要实现、公开要求到消费者及最终值的映射、验证记录和未决项。更新受影响题目、文档与产物引用，清除被替换入口及调用。实际数据、执行环境不足时明确未完成的绑定／限额／安装验证；配置完成、参考精度、预算校准和正式发布分别报告。
