# 实际数据与契约审计

目标：逐项建立全部实际输入、公开输出与三文件契约的对应证据，发现数据越界、文档漏定义及相互冲突。独立考生可实现性审阅由 [caeoj-candidate-review](../caeoj-candidate-review/SKILL.md) 拥有，问题族设计审阅由 [caeoj-design-review](../caeoj-design-review/SKILL.md) 拥有；本技能不自动执行它们，也不将维护方读过实现后的核查称为独立考生审阅。

## 输入与范围

定位用户指定的 qbank 题目目录和仓库根目录，使用用户指定或项目已激活的 Python 环境。先读取该题 instruction.md、DATA.md 与 docs/CONTRACT.md 作为数据对照依据，再枚举 cases、samples、examples 内全部实际输入与公开输出。维护领域资料或实现可用于之后定位问题，但不能用它们补足公开文档后宣称题意完整。不要求题目存在 generator 或 baseline。

默认只审核并输出报告；用户明确要求修复时再修改公开文档。题面、协议、实际输入相互冲突时，记录冲突并确认依据，不能默认实际输入必然正确，也不能修改数据迁就实现错误。

## 先检查三文件阅读边界

本题全部物理字段、材料响应、条件、采样及观测应在 DATA.md，任务、方法责任、资源和评分应在 instruction.md。CONTRACT.md 只承担通用规则。不接受由 COMMON、章节共享 DATA、领域维护规范、其他题或源码才能拼成完整定义。旧题存在额外依赖时记录为文档问题，不擅自删除用户未授权的材料；授权修订时逐题内联适用内容并复核，不能机械复制所有模型分支。

对照当前 CONTRACT 区分通用结构与领域声明检查。网格统一为 Gmsh MSH 4.1 ASCII，场数组采用 HDF5；物理声明按本题明确的配置形式读取，不用“旧格式／新格式”代替准确字段定义。维护实现定位见[运行装配说明](../../../qbank/maintenance/RUNTIME.md)，不让考生依赖它补题意。

保留数据对照所需的三文件完整性核查；完整的独立考生审阅可复用版本及覆盖匹配的既有记录，需要补审时交协调方调用对应技能。结构验证、真实数据对照及数值／物理验证分别给出状态；无实际数据时报告审计资料不足，不以文档检查或临时 fixture 代替实际数据审计。

## 先盘点事实

按当前格式核对数据池选样中的 case ID、条目描述绑定、角色、装配映射及依赖闭包；不再把清单当作镜像文件列表。池中存在条目不表示本地已装配。首批已有池数据，但通用装配工具尚未实现，不臆造可用命令。

题目存在 `data-manifest.json` 时，先按[数据获取与维护](../../../qbank/maintenance/DATA-SYNC.md)定位并获取 HF 数据，对照清单核对文件、大小、SHA-256、输入／参考分组和共享依赖。clone 后没有本地目录不表示远端无数据。清单完整性不等于数值审核通过；当前无专用同步或清单校验工具，不假称自动检查已生效。

运行本 Skill 的辅助脚本（将 `<skill-dir>` 替换为本 SKILL.md 所在目录）：

```sh
python <skill-dir>/scripts/inventory.py --task qbank/<chapter>/<section>/<task> --output runs/data-review/<task>/inventory.json
```

命令的 --task 传入题目的实际目录路径。脚本当前仅自动发现 cases/*/problem.json 与 samples/*/input/problem.json；对 examples 以及其他布局另行完整枚举并补充同类盘点，不得把脚本返回零输入当作不存在数据。

结构检查使用与本题匹配的已装配工具，可用 `python -m caeoj info --input <problem.json>` 核对支持范围；独立核心的通用结构通过不能代替完整题目契约检查。

脚本只盘点完整 JSON、HDF5 dataset 元数据和网格文件头，不求解方程、不读取数值标答内容、不执行题目代码。它不是校验器，更不判断文档是否合格；退出成功仅表示盘点完成。检查报告中的缺失或不可读文件，必要时使用现有 `caeoj validate-input`／`validate-output` 核对结构。

必须遍历全部实际输入，汇总同一字段或条件的所有变体及出现／缺失情况；不用一个样例代表全部输入。大数组先读头部，按需检查小切片，避免为审核文档加载整套轨迹。数据未补齐时继续审核可获得的元数据，明确哪些内容未经验证，不能把这类题目判为完整通过。

## 逐项对照

建立“实际 JSON 路径或 HDF5 key → 文档位置 → 约定 → 支持该结论的输入文件”的覆盖关系。至少检查：

- **文件与引用**：入口、相对路径基准、网格／几何职责；`conditions` → `fields` → `array` → HDF5 的完整引用链。区分字段名、数组 key、位置名、Physical Group、实体 tag 和数组行号。
- **嵌套对象**：各类条件的公共字段、`data` 内的全部必需／可选字段，子字段的类型和单位；常量对象、场引用和数组不是可互换的表示。每种实际 role/operator 组合都须有完整结构说明，不能只列算子名称或公式。嵌套／表示差异易误读时用代表性可解析 JSON 片段说明；结构表已能逐键还原时不强制为每个算子重复示例。
- **条件出现规则**：每个可选参数和条件专用字段的准确路径、类型、出现条件、缺省含义。检查既有字段存在的输入，也有字段缺失的输入；缺失不能被擅自解释为零。说明条件顺序、角点重合或多条件并存的语义（如适用）。
- **数组与关联**：每个输入／输出 key 的 dtype、完整逻辑 shape、轴含义、时间轴、分量顺序、位置及 IDs 的对应关系。边界节点与边界单元、初始时间轴与输出时间轴、输出时刻与内部步长不能混淆。存储字节顺序与逻辑轴顺序按通用协议区分，不额外要求字节唯一。
- **数学含义**：参数和系数的单位；坐标、法向、通量符号、归一化变量；数组表示点值、平均值、积分值还是函数系数；连续函数或插值规则在哪里定义。只检查定义是否完整且相互一致，不推导求解算法或以算法习惯替代题目定义。
- **范围与输出**：题面范围是否涵盖输入中的格式和条件组合；输出声明、必需复制的 IDs／时间轴、允许的 key 是否讲清。实际数据超出题面时作为数据问题单列，不能只扩大文档范围掩盖问题。

区分“描述散落但明确”和“必须猜测才能实现”。按程序能否无歧义地读取数据判断，不以文档是否包含某个关键词判断。通用规则可准确引用 CONTRACT.md；题目专用字段与算子参数应在 DATA.md 讲全，不给 CONTRACT.md 累积题目补丁。

按数据或工具变更风险从最终 DATA 构造少量合法／非法变体，核对“文档允许但工具拒绝”和“文档禁止但工具接受”两种方向。可沿用已有 fixture 作载体，但预期应来自公开契约，而非同源生成器或被测 helper。没有正式数据时这只提供契约／工具证据，不算实际数据审计；不要为低影响措辞修改机械补测试。

## 验证示例与形成结论

解析文档中的 JSON 示例，核对其层级、名称、单位和字段引用；片段须明确标注为片段。与公开样例对应的示例应逐项一致。先审查读取示例代码，区分原样读取与显式时间采样；基础读写不隐式插值，使用 `sample_field` 时必须有明确 sampling 声明。再在临时目录或输入副本上执行；覆盖每种实际条件／字段变体，不能把运行无异常当作物理解正确。

结构校验和数值判分职责保持分离。不向校验器加入物理验证、系数纠正或边界组合补救；不在公开文档中写入隐藏测试点名单、标答、解析解、弱式推导、推荐算法或为某个失败 solver 定制的修补提示。对照隐藏输入得到的证据只进入维护方审核报告。

默认报告保存到 `runs/data-review/<task>/report.md`，最终回复简述结论与最重要问题。报告包括：

1. **覆盖范围**：实际读过的输入数、条件变体、示例，以及缺失材料或未执行的验证。
2. **问题表**：严重程度、缺漏／歧义／冲突、实际字段路径、文档位置、输入证据、对程序的影响、最小修订建议。将文档问题、数据问题和资料不足分别说明。
3. **验证与结论**：运行的检查及结果；结论为“通过”“需修订”或“资料不足，未完成”。存在影响读取的未定义字段／分支或未解决冲突时不能判为通过。

记录所审文件版本、实际检查范围及剩余限制；“通过”仅表示这些检查未发现未决问题。后续复审发现缺陷是正常反馈，补充有区分力的反例和回归，不以固定轮数或问题数量代替判断。

若发现题面本身欠定／矛盾，反馈出题环节，不通过修改数据或偷偷增添闭合消除问题。若授权修订，可结合 caeoj-design-data，仅补足接口定义和必要的格式示例；修改后重跑可用示例及相关检查。修订后同步本技能及相关设计／配置技能的接口说明，核对已有公开包是否过期。发布器当前按唯一 slug 定位 `qbank/<章>/<节>/<题目>/`，要求完整公开样例和显式 `grading.json`；prepare_harbor 另需真实隐藏输入与参考。本次范围包含打包或评测运行时才重新打包并组装，缺少数据或不在范围时注明“需重新组装／未发布”，不制造假样例或移动题目绕过前置检查。保持题目数值数据、解法与通用评测流程的修改在用户授权范围内。
