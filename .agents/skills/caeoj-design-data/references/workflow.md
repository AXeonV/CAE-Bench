# 从题面到 DATA.md

## 1. 提取需求并识别题面问题

先读题面与 CONTRACT，区分任务事实、考生自由、算例变化量和要求输出的观测，再检查已有 DATA 及工具。维护实现和来源不是题意的替代品。

| 需求 | 需要确定 |
|---|---|
| 分析对象 | 物理维度及降维含义、区域、材料／状态、稳态／瞬态／统计目标 |
| 物理信息 | 初态、边界、源、库存和基准；哪些材料响应已给定，哪些模型允许考生选择 |
| 连续数据 | 点／实体、坐标、分量、单位、空间重建、时间及外推、唯一迹 |
| 观测 | 位置／区域、时间／统计窗口、通量方向、载荷作用对象、平均与积分 |
| 组合 | 合法与禁止组合、出现规则、可检查的声明约束及需数据保证的物理条件 |

尝试用两种合理解释读取同一题面。若会得到不同问题或观测，记录具体影响并反馈题面；别用“算法自由”补足缺失的物理条件。模型选择自由不允许改写给定材料响应，来源配置也不能变成隐藏模型约束。

题面缺失时不只输出一份字段表假装已完成：在出题任务中回到 author-section，按既有规划补题面；独立 DATA 任务中先提出缺失信息与可审查方案，完成不依赖它的部分。对改变用户目标的选择请求澄清；不默认把每个接口设计决定都变成审批。

## 2. 设计本题可独立读取的契约

将需求映射到清单、场和条件，用已有带单位常量、类型化引用、location、time_axis、sampling 和 aggregate 等结构表达；不能仅因为新领域而重造格式。字段名称和枚举是物理对象的表达，不能隐藏数值算法或求解控制参数。

DATA 至少覆盖下列内容，按本题需要组织，不要求照抄固定标题：

- **入口与引用**：清单、文件、路径基准；条件到 fields 再到 array 的引用链；对象名、数组 key、Physical Group、实体 tag 与数组行号的区别。
- **分析与参数**：准确 JSON 路径、全部必需／可选键、类型、单位、值域、出现条件、缺省的真实含义；分析模型／版本标识不可只靠 task 推断。
- **物理解释**：本题固定的材料响应、状态关系、条件及观测含义就地写清；不替考生固定题面保留自由的闭合。无需为 CAE 题附解法、弱式推导或推荐离散。
- **条件结构**：全部 role／variable／operator 和 data 键集合、标量／场／选项表示、物理符号、区域、时间及组合规则。各字段 quantity 的允许值或明确不限制的标签规则须写清，不能只靠单位猜用途。
- **数组与连续解释**：dtype、完整 shape、分量、位置与 IDs、时间轴；空间／时间重建和外推；节点转实体平均的顺序；初态与请求时刻不同于内部时间步。
- **观测**：必需与可选输出、点值／加权平均／积分、导数及界面迹、二维厚度、压力和力的基准、输出 key 与复制的轴。不能用假点表达区域整体量。

嵌套／表示差异易误读时提供代表性 JSON 片段；结构表已能逐键还原时，无需为仅名称不同的算子重复示例。已有格式片段必须可解析并标注为片段，不冒充可运行样例。例子的数值、字段名和区间不是固定值时明确说明。仅保留本题适用分支；层流不混入湍流平均，二维不让考生阅读三维题来找补充，稳态不混列瞬态初态或多帧变化要求。

考生文件只依赖本题 instruction、DATA、CONTRACT。资源与评分完整留在 instruction，含实际指标、聚合、阈值和固定偏置，不让考生再找 GRADING 或维护记录。维护资料位于 qbank/maintenance，不作为并列契约，也不随公开工具包打包。

## 3. 判断是否需要拓展基础设施

区分以下情况，避免以“拓展协议”取代实际 DATA 交付：

| 缺口 | 处理 |
|---|---|
| 已有结构、物理语义和工具足够 | 写好本题 DATA；无需改通用协议或加一层领域文档 |
| 已有结构可表达，但新增物理语义需要支持 | DATA 定义语义，按需补领域检查、SDK及验证；维护说明可选 |
| 缺少实体／引用／采样等通用表示 | 修改 CONTRACT、Schema、通用读写及必要下游，同时更新本题 DATA |
| 问题本身欠定或矛盾 | 反馈题面；不能靠增加任意默认值、隐藏投影或缩小题目绕过 |

变更前记录拥有层、受影响读者和兼容决定。相同 JSON 会产生不同物理解读时，即使字段名未变也属于语义变化；按现有版本策略说明迁移，不盲目递增，也不暗改旧数据。CFD 的四键启用只是实例，不是新题的固定模板。

按实际影响同步：Schema 管结构、类型和未知键；通用检查管引用、shape、dtype、IDs 和时间；领域检查管可判定的单位、参数及组合；SDK 精确读取与显式采样；评分配置匹配题面；发布器交付必要运行模块和考生文件，并排除维护资料。不需要改变的层说明理由，不制造无意义代码。

通用错误先处理，再访问领域字段；缺参数或畸形引用应返回诊断，不能 KeyError，也不以宽泛捕获掩盖缺陷。保留旧错误类别／路径与退出行为；整数元数据不能误接受 bool 或 2.0。昂贵几何和连接关系按需加载，保护旧大网格任务的内存及启动行为。校验器不补物理、不转换单位、不修复答案，不宣称已证明物理适定或数值准确。

## 4. 按变更风险验证

纯文档设计首先核对字段覆盖、可解析片段、三文件依赖、分支与符号一致性，不为低影响文字调整机械加测试。新增或改变工具时，按需要验证：

- 最小合法输入及输出 roundtrip，覆盖关键配置，不机械枚举所有物理属性的笛卡尔积。
- 缺／多参数、错单位、错引用／位置、时间覆盖不足、非法组合及范围边界。
- 独立手算的材料响应、插值、简单几何积分／法向、相质量或统计量；不让被测 helper 自己生成预期值再自证。
- 非连续 tag、不同排列、边界方向及节点／单元、平均／积分的区别。
- 代表性旧合法输入、非法诊断和相关回归；有性能影响时检查相应开销。
- 公开工具包在独立进程中使用，核对实际导入路径；不能由本机 editable checkout 掩盖依赖遗漏。检查包中没有 qbank/maintenance 文档。

用现有项目环境，不覆盖非空目录。临时解析 fixture 不写成正式案例，不证明一般求解器、数值精度或物理模型有效。已有真实数据时交由 audit-data 完整盘点，注意 inventory 的发现范围，不能用零输入报告代替实际检查。

## 5. 联合审阅、反馈与交付

独立考生审阅只提供最终三文件和实现任务，不提供维护规范、作者算法或隐藏材料。检查是否能完整读取并确定问题、是否需要追引用、是否存在两种合理物理解读。原实现方另查工具与测试，文档审阅不能证明实现正确。

修订后由审阅者复核最终文件；可与总出题流程共用一次联合审阅，不因技能切换重复审阅同一未变版本。共享实现变化时同步全部受影响题目的自包含 DATA，并重查相应证据，不用维护规范的一处修改代替逐题更新。

交付 DATA、必要的 instruction 修订、实际需要的工具和验证证据；维护记录保留需求映射、兼容决定、问题处理及剩余限制。分别报告契约审阅、基础设施、实际数据审计、数值／物理证据、发布状态；没有数据不妨碍契约交付，也不构成真实数据审计通过。
