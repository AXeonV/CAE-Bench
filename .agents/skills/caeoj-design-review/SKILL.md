# 设计审阅

协调方列明单题、节、章或全库范围，以及规划／已成题阶段。材料为[题库哲学](../../../qbank/PHILOSOPHY.md)、目标规划、instruction.md、DATA.md、CONTRACT.md；比较边界时显式纳入必要相邻材料。规划阶段无需题面；已成题缺文件须记录资料不足，不转换阶段掩盖缺口。

组织独立 subagent，使用新上下文（支持时 `fork_turns="none"`）。只给真实任务、材料白名单、检查方法与报告目的地；不提供作者推导、既有结论、隐藏数据、参考解或实现。无法独立审阅时如实报告，作者检查只能称自审。整章／全库可分组，但逐题记录覆盖，并另查跨组边界与重复。

检查：

- **能力定位**：公开范围是否形成有意义的可复用问题；尝试两个有实质区别的合法输入，判断固定算例解法是否覆盖承诺。参数可变本身不足以证明设计合理；基础设施测试按其用途判断。
- **范围与划分**：限制有无能力依据，相邻题差异是否真实，是否过宽、机械组合或任意拆分。同一 solver 能做多题不直接等于冗余。
- **来源独立性**：替换来源后任务含义是否保持，来源配置是否变成隐藏条件；设计覆盖和已有数据覆盖分开判断。
- **建模与评价**：固定事实、考生自由和观测／评分是否一致；自主建模不能被某一模型的专有输出暗中取消，明确给定 PDE 或方法目标也可以合理限定模型。
- **层级与覆盖**：哲学、规划和题目是否对应，有无遗漏或跨章冲突。规划可被质疑，但不擅改用户既定目标或编号。

默认只写 `runs/design-review/<本次目录>/`。报告记录材料路径／SHA256、基线与未提交状态、覆盖／缺口、比较对象；发现给出位置、影响、反例或能力差异和最小建议，区分缺陷、待核实及可选优化。科学判断不确定时保留限制，不凭印象判错。

按上述维度给出“需修订”“资料不足”或“本轮未发现未决问题”；结论不能外推到数值可行、预算或隐藏 judge 公平。修复交调用方，设计变化后复核受影响范围，复用其余结论先核对版本。保留分歧，不设固定问题数或审阅轮数。

本技能不自动启动出题、数据审计、benchmark 或发布。设计审阅和考生审阅使用不同上下文，设计解释不交给考生补题意。
