# CAE I/O 协议设计与拓展

读取仓库 `docs/CONTRACT.md`、目标题目／章节规划、适用的配置规范，以及 [出题与协议经验](../../../qbank/design/AUTHORING-LESSONS.md)。按 [协议工作流](references/workflow.md) 实施本次明确需要的变更；不照搬 CFD 的材料模型、单位、边界或版本号到其他领域。

先从物理输入和可比较观测建立需求，不从现有 Schema 猜物理。区分“已有结构缺解释”“需要领域配置”“确实缺通用表示”；足够时复用，不为每章重造协议。输入固定物理事实与材料信息，不以来源软件或 task ID 隐式固定考生的模型／算法。

实施前记录变更拥有层、兼容性及受影响文件。相同 JSON 若会得到不同物理解读，属于语义变化，即使 Schema 没变也须评估版本／迁移；不能将其掩饰为纯措辞修订。遵从仓库现有版本策略，不每次机械递增，也不擅自重写旧数据。

交付覆盖规范、Schema、通用及领域检查、SDK、协议最小示例、相关测试和受影响的公开包依赖。只改语义且表示未变时，不为凑清单制造无意义代码；说明哪些层无需改变及原因。校验器拒绝不相容声明，保留结构／引用诊断，不猜测缺省物理、不转换单位、不修复答案。

合法输入、非法组合、旧协议和隔离后的公开工具包都需要相应证据；具体测试按变更风险选择。优先用最小解析对象、几何恒等式和独立计算预期值验证接口；不把同一 helper 生成又验证自己的结果当作独立正确性证据。大型旧任务按需加载，保护旧行为与内存开销。

新物理语义或关键表示完成后，组织独立 subagent 仅依据公开协议／需求只读审阅其可实现性，再修订并复核；实现方另对代码、测试及打包负责。缺少独立工具时如实报告审阅未执行，不阻止其余可完成工作，也不冒称通过。

本技能允许在临时目录制作协议验证 fixture；若用户要求题库数据留待后补，不向 examples／references／cases 写入数据或替代正式参考。涉及已有数据时按 `caeoj-audit-data` 审核全部实际变体，注意它的 inventory 不自动发现 qbank/examples。正式发布仍按用户任务范围执行。

维护记录列出：需求到声明的映射、兼容／迁移决定、实际验证、未覆盖范围及公开包状态。最终区分协议可用与真实物理／数值验证，不以回归测试数替代后者。按用户偏好提交本次修改，保留无关工作树内容。
