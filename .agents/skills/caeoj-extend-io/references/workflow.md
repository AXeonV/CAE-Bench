# 协议拓展执行流程

## 1. 从目标建立缺口表

阅读目标题面／规划以及协议拥有实现，定位仓库实际路径，不假设每个领域都使用 CFD 配置。以表或简短记录回答：

| 需求 | 应明确的信息 |
|---|---|
| 分析对象 | 物理维度、降维含义、域／区域、材料与状态、稳态／瞬态／统计目标 |
| 条件 | 输入固定的信息、建模自由、相容性、唯一性、是否缺初态或必要边界 |
| 连续数据 | 实体身份、坐标、分量、单位、点值／平均／积分、空间重建、时间及外推 |
| 观测 | 对应物理量、区域／位置、时间／统计区间、通量方向、载荷作用对象及基准 |
| 组合 | 哪些属性正交复用，哪些组合禁止，约束应由谁检查 |

每行映射到已有 JSON 路径／数组和规范位置，标记复用、语义补足或结构缺口。对关键条件尝试两种合理解释：若二者对应不同答案，必须消除歧义。不要以“数值实现自由”替代完整物理条件；区分模型输入与解法建议。

## 2. 选择拥有层及兼容方式

- **题目专用约束**：限制已有能力的组合，放题目 DATA.md；不修改全局格式。
- **领域配置语义**：在共享结构上固定该领域的材料、条件、采样和观测，放领域规范及专用检查。
- **通用表示拓展**：新种类位置、引用、采样或数据结构确为多个题目所需，才修改 CONTRACT.md、Schema 与通用读写。

说明旧合法输入如何读取、旧非法输入如何诊断、新能力如何启用。必要时显式 opt-in 配置／版本，禁止新旧两套字段重复表达同一事实。物理或单位意义改变时需迁移／版本说明；不能仅因字段名未变就宣称兼容。尚未发布配置的修订也须同步所有拥有定义的文档，检索已有 fixture 和读者，记录影响。

CFD 版本 2 的四键成组声明是已有案例，不是未来任意扩展都必须用的模板。兼容不等于可以接受一切组合，也不等于永远保留错误语义。

## 3. 完成声明与实现

对新增字段明确：完整路径、类型、必需／可选条件、缺省的真实含义或禁止缺省、精确单位、允许范围及关联。不用裸字符串暗藏函数代码或任意可执行表达式。

条件使用字段表配合可解析片段说明层级；每个参数都必须能够定位。说明输入的点／实体平均如何转为连续边界或物性，及整体观测使用何种积分／平均。不以假点、虚构坐标或重复全局字段维持旧数组形状。

检查各实现层：

| 层 | 责任 |
|---|---|
| Schema | 字段结构、类型、枚举、未知键；留意整数与 bool／浮点的区分 |
| 通用检查 | 引用、shape、dtype、IDs、时间、数组 key、位置类型与通用关系 |
| 领域检查 | 单位、参数集合、合法组合、压力／势基准、初态及区域覆盖等可判定声明约束 |
| SDK | 精确读取声明、显式采样与几何操作；不偷偷重建、单位换算或改变模型 |
| 输出／判分 | 数值结构与内容比较分离；评分配置不混入物理输入，适用时复用现有指标 |
| 发布工具 | 新运行模块、规范、依赖和共享文档随实际公开包一并交付 |

先处理通用结构错误，再访问领域字段；畸形引用或缺参数应产生诊断，避免 KeyError／崩溃。验证错误路径及类别兼容，别通过宽泛捕获异常掩盖真正缺陷。新增昂贵几何／连接关系按实际需要加载，避免所有旧网格付出内存成本。

输入检查只证明结构和声明满足已实现规则，不证明网格质量、物理适定、模型有效、稳态存在、无回流或解误差。哪些条件由数据制作方保证，应在规范与维护记录中明确。

## 4. 用具体证据验证

根据变更选择测试，不要求机械构造所有属性的笛卡尔积：

- **最小合法输入**：关键维度、材料、分析类型及条件组合可读取；输入—输出 roundtrip 不丢身份与时间轴。
- **非法／边缘输入**：错单位、缺／多参数、错误引用、错误位置、时间覆盖不足、不相容约束、重复区域、零／负值，以及明确不支持的组合。
- **独立数值预期**：材料响应的手算点、线性时间插值、简单边界积分、法向与闭合面恒等式等；避免与被测 helper 共用同一实现生成预期值。
- **排列与语义**：非连续 tag、不同存储顺序、边界单元方向变化；节点／单元、平均／积分不可混用，周期匹配不靠行号。
- **旧行为**：有代表性的旧合法输入、旧非法诊断及现有回归；新增大数组加载路径有性能影响时检查相应开销。
- **公开包隔离**：在临时目的地组装工具包，用独立进程从包中导入并确认模块路径，不让本机 editable checkout 掩盖遗漏。无实际公开样例时只用临时协议 fixture，不发布空题目。

使用项目现有 Python 环境。现有 CFD 模式可参考 `tests/test_cfd_contract.py` 与 `src/utils/make_cfd_examples.py`，但解析静止流 fixture 只证明这些接口路径，不能用来声称一般 CFD 精度或全部边界均已物理验证。临时生成器拒绝覆盖非空数据目录；实际数据变化另做完整审计。

## 5. 审阅与交付

独立审阅只提供公开协议、目标物理描述与需要读写的接口任务，不提供作者预期结论或实现来补足文档。要求指出同一输入是否可产生不同合理解释、未定义的读取／采样分支、单位／符号／基准及兼容冲突。代码与测试另由实现方核查；纯文档审阅不能证明实现正确。

修订后复核最终版本。维护记录至少保留缺口表、兼容决定、修改清单、验证证据、未验证物理和实际数据范围。若尚无数据或未发布包，如实分别报告；不将本次协议 fixture 冒充题目算例。涉及正式题目的读取文档变更，交给出题技能更新题面并按数据审核技能核对真实输入。
