# 题内数据池维护

定位题目、实际来源材料和用户要求的操作。先读本题 `data-manifest.json`、[数据池设计](../../../qbank/design/DATA-STORAGE.md)及[操作指南](../../../qbank/maintenance/DATA-SYNC.md)，使用 `python -m caeoj_tools.cli data` 的现有命令；不重新写一套同步脚本，不将工具返回成功解释为数值审核通过。

操作按实际需要组合：生成材料的离线 `pack` → 核对 bundle 与完整性 → 用户已要求发布时 `upload` → 明确 `select` → `fetch`/`assemble` → `verify` 和真实消费检查。纯拉取不需要重新制池或上传；纯 DATA 设计不触发数据制作。新题 ID 需显式分配并检查全库唯一。

上传使用既有登录与最小必要访问，不把令牌写入仓库或日志。相同文件跳过，远端差异先报告；用户已授权更新后才使用 `--update`。父提交冲突先重新核对远端，不无限重试或覆盖别人的修改；核验失败记录提交 ID 与未完成部分。

选样保存明确 case ID、描述摘要、角色与本地编号；输入和来源轨迹不得重复选入独立测试。参考不齐只能用于开发。样例从池条目复用，不制作重复权威副本，也不把整池索引、作者证书或非样例参考混入考生材料。

本地装配前检查差异，显式更新才覆盖；被修改的旧装配文件与未知文件不得静默删除。不要编辑回执骗过校验。数据变更后核对受影响的样例、参考、契约与评分消费链，并记录实际执行范围。

开发检查允许 warning，正式 benchmark 需要严格校验；现有历史重叠应交选样修订处理，不能关闭检查。涉及物理、DATA 或数值参考制作时交对应设计/审核流程；本技能不放宽判据、不补造参考，不默认上传未授权材料或启动模型评测。
