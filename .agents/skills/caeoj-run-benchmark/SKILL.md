# 运行题目 benchmark

先确认用户指定的题目、模型及执行主机，读取本题 instruction.md、DATA.md、评分／运行配置和已有数据状态。按[执行流程](references/workflow.md)推进；当前 Harbor 命令、监控和结果入口见[后端线索](references/harbor.md)，每次仍核对实际版本与 --help，不照抄历史运行命令。

日常评测主线为确认数据就绪 → 打包并统一组装 → 启动监控 → 运行 Agent → 汇总结果。首次安装和数据制作属于按需准备；开发回归、手工结构诊断、Oracle 和单点复核按变更或诊断需要执行，不把它们变成每轮必跑项。命令示例见 [README 运行指南](../../../README.md#运行)。

题目存在 `data-manifest.json` 时，按[数据获取与维护](../../../qbank/maintenance/DATA-SYNC.md)获取并核对所选 case 的输入、参考及共享依赖；完整性声明、实际文件、大小或 SHA-256 不符时停止正式 benchmark。当前装配器不自动执行清单检查，需在维护方前置核验并留证据。HF 数据全网公开不改变考生包的材料白名单，不把整题清单或非样例参考交给考生。

调用本技能运行 benchmark 即包含本地材料准备、执行及监控，无须逐项重复批准。模型、收费规模或执行主机未确定时，优先使用用户已确认的本次配置，否则只询问真正缺失的选项；不能从当前助手型号推断被测模型。未指定重复／并发时，采用一次、并发一并明示。数据审计、装配和监控准备可以先行；不得在模型或必要约束未明确前启动收费 trial。

检查公开样例、全部隐藏输入及对应参考的完整性和契约绑定；必要时调用 [caeoj-data-review](../caeoj-data-review/SKILL.md)。核对当前框架实际消费的配置、评分、隔离和资源，必要时调用 [caeoj-configure-judge](../caeoj-configure-judge/SKILL.md) 修复明确的基础设施缺口并回归。发现题意、数据或判据问题先记录并处理相应环节，不生成假数据、不补造参考、不放宽阈值来让 benchmark 开始或提高成绩。已有 provisional 题可做注明阶段的试运行，不要求凭空宣称已校准。

设计和考生审阅记录可按版本及覆盖复用，不作为每轮运行必须重做的步骤；若发现相关缺陷，反馈当前协调方，不能在冻结运行中自动改题或启动全套出题。

冻结明确的池 case ID、条目描述摘要、测试／样例角色及装配结果，检查重复轨迹、输入重叠和旧装配残留；索引变化不能自动改变本轮选样。按实际池格式消费，不把尚未实现的通用按 ID 装配或远端恢复当作可用命令；迁移保留的既有重叠需作为选样问题处理，不能因摘要一致就宣称正式就绪。

本题必须有显式评分策略；策略缺失或执行配置重复提供容差属于准备错误，交配置技能处理。SDK／契约、评分或公开材料改变后，核对并重建过期 ZIP 与 Harbor 目录。当前装配边界见[运行说明](../../../qbank/maintenance/RUNTIME.md)。

运行前保存有限的运行计划、版本与内容哈希、模型／推理参数、重复数、并发、预算、目录及准备状态。冻结题面、数据、参考、策略和资源；按用户意图保留一次 solver 冻结后逐例独立判题，不能让考生通过隐藏判分反馈反复改解。若确需修评测条件，另建明确版本和运行，不拼接成同一成绩。

**启动 Harbor 监控是标准步骤。** 在执行主机启动实际 Harbor Viewer，指向本轮使用的 jobs 根目录；显式固定默认端口 8080，默认监听 0.0.0.0，使用户可访问 `http://127.0.0.1:8080` 或 `http://<执行主机本地IP>:8080`。0.0.0.0 监听所有 IPv4 接口，实际访问范围由主机网络决定；不自动改防火墙或建公网隧道。核对 HTTP 健康、配置中的目录和模式、实际 HTML 页面；API 存活不等于页面可用。空 jobs 目录显式使用 --jobs。

先复用能够确认属于同一 jobs 根目录的已有监控；默认端口冲突时不杀其他服务、不擅自换端口或谎报 8080 可用，查明占用并给出具体处理选项。监控失败先修复或明确反馈，不悄悄省略后启动评测。POSIX 主机可使用本技能的 [viewer.py](scripts/viewer.py) 管理启动／状态／停止；其他系统用原生进程工具实现同样核查，不假称辅助脚本跨平台可用。

后台启动监控和长任务时记录 PID／工具会话、命令、日志和目录，不能用无人管理的 shell `&` 后宣称已运行。监控独立于 job 生命周期，评测完成后默认保留供用户查看，在最终交付提供访问地址、状态／停止方法；只有用户要求或清理本次失败测试时才关闭自己创建的服务。远程执行时地址属于远程主机，不能把助手所在机的 localhost 当成远程监控；跨网段确需转发时先明确实际连接方式。

先确认监控可用并及时告知可点击 URL，再启动本次 job，保存实际 job 名称／ID与路径。使用当前 Harbor 参数核对重复、并发、资源与模型选项；生成候选阶段与 verifier 阶段分别记录，必要时执行已有 Oracle 检查，但不把 Oracle 通过视为一般数值参考可信。

持续跟踪 job、trial、verifier 和报错，区分 solver 数值失败、程序／超时／格式失败与数据／参考／框架错误。不要因看到一个 result.json、reward 或进程退出就宣称全部完成；检查计划 trial 数、实际终态、逐例数量及报告完整性。失败 trial 的重试须区分基础设施补跑与独立求解尝试，不默默多跑收费尝试或挑最好成绩。中断后先核对已运行进程和文件，再按冻结计划续作，避免重复启动。

最终报告每次尝试及逐例成绩、汇总通过率／分数、时间和实际可获得的用量／费用（未知不估造），保留失败分类、未完成项、日志与复现记录。基础设施错误不混作 solver 失败或从分母静默删去；不得只报最好一次。指出结果衡量的参考一致性与校准边界。报告监控访问地址和是否仍在运行；只在本轮数据与运行全部满足完成条件后宣称 benchmark 完成。

命令、目录、装配、判题状态或汇总口径变更时，同步本技能的流程／后端参考和 README 操作指南。历史成绩只对应其冻结的题目、数据、策略及运行条件，不把已移除任务或同类旧题的成绩当成本次验证。

运行产物放忽略的 runs 目录；不把 API key、令牌或完整敏感环境写入计划／日志摘要，也不自动上传 Harbor Hub、推送或更新 PR。创建／修订本技能本身不触发正式模型评测；测试可使用临时空 jobs 和可回收监控进程。
