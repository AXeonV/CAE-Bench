# 运行 benchmark

按[执行流程](references/workflow.md)完成“就绪检查→冻结及装配→监控→运行→汇总”；Harbor 命令、Viewer 及结果入口按需查[后端操作](references/harbor.md)，执行前核对本机版本和 `--help`。

确认题目、模型／适配器、执行主机及必要预算，优先沿用用户已确认配置；不能从当前助手型号推断被测模型。重复和并发未指定时各为 1 并明示。必要信息未明确前可准备材料，不启动收费 trial。先查活动运行，区分新求解、续跑和冻结提交重判，避免重复调用模型。

有 data-manifest.json 时按[数据池操作](../../../qbank/maintenance/DATA-SYNC.md)装配并严格校验。题目、样例、全部所选测试／参考、各case评分及执行配置必须匹配；完整性或重复选样失败即停止处理，不绕过前置检查。新数据或契约疑点交数据审计，配置缺口交配置技能。独立审阅记录按版本与覆盖复用，不要求每轮重做。

冻结题面、数据／参考、case ID／描述摘要、HF 提交、case配置／参考与评价实现闭包、资源、公开包、模型参数、尝试数和重试边界，保存运行计划；变化后另建明确运行，不混算成绩。求解提交冻结后逐例独立判题，不用隐藏反馈反复修改答案。

运行前必须确认执行主机上的 Harbor Viewer 可用，并告知访问 URL。默认绑定 `0.0.0.0:8080`，核对 jobs 根目录、健康接口与实际页面；复用同目录服务，不杀无关服务或静默换端口。无法恢复时说明原因，用户明确接受降级后才继续。进程记录及具体核查见参考。

跟踪全部 job／trial／verifier，按计划数量、终态和逐例覆盖确认完成，不能只凭单个 reward 或进程退出判断。区分数值、程序／超时／格式及基础设施错误，基础设施补跑和新的独立求解尝试分别记录；不擅自增加收费尝试或只选最好成绩。

交付每次尝试、逐例及汇总成绩、明确分母、失败与未完成项、日志／复现记录和可取得的时间费用（未知注明）。监控默认保留供回看，提供地址、状态及停止方法。运行资料放 runs，不含凭据；不默认上传、推送或发布。修订本技能本身不触发正式评测。
