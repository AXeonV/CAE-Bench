## 逐项判断

### 能力定位、目标与边界

规划第 3、5 行明确固定二维三角形节点速度场、完整回传以及无 PDE 认证，与第零章“不考查物理求解能力”的声明一致。题库哲学要求问题族覆盖，但不意味着基础设施题必须人为加入物理求解。

概念上取两个有实质差别的合法输入：一个三角形上的常量双分量多帧场；一个由多个共边三角形承载、各节点值形成非全局仿射分布的多帧场，且 x/y 数值不对称。固定输出算例无法同时覆盖二者；按清单完整回传的程序可以覆盖。第二类还可区分真正逐单元 P1 评价与错误的全局拟合。此处是范围检验构造，不代表实际数据已有覆盖。

### 与旧题区别及范围划分

0.1 DATA 明确无插值、支持维度／类型／位置变化，题面以全部回传值逐值比较判分；新规划则收窄提交数据类型，重点覆盖整场、稀疏分量选择、独立检查 AND 的评价路径。两者提交程序可共享回传实现，但基础设施测试所验证的组件不同，不能据此认定重复拆题。

六个测试类别和两个公开样例的分工能表达预期评价路径；非连续 tags、多时刻及不对称值与轴映射错误相关。未见要求修改既有物理题或引入领域特例进入通用协议。

### 来源独立性

规划由输入目标场和确定重建定义参考，未将 HF 身份、数据来源或原始软件配置作为求解条件。更换数据来源仍可保持回传及评价含义。HF 的具体装配可用性和实际参考生成正确性不在本轮证据中。

### 任务、模型和评分一致性

完整输出契约与稀疏观测参考可以并存，符合 CONTRACT 第 9、11 节：先独立校验完整输出，再按 case 检查评分。配置不能追加输出，公开题面给全目标与所有判据，避免考生依赖私有配置补题意。

稀疏检查不必证明整个回传场数值正确。例如仅选 x 检查时，结构合法但 y 值错误的提交可能得分；这正是分量选择的可观察行为，不能据成绩宣称完整场正确。规划第 11 行已安排“未观察分量”验证，因此未发现其将稀疏评价误认为全场证明。

全部选中检查通过得 1 分，适合验证 AND 行为。固定目标是输入场，未赋予自主物理建模责任，因此 P1 重建和严格绝对误差不构成取消建模自由的问题。

## 成题时需明确的语义与验证建议

以下是从规划走向题面／DATA 时的补全项，**不是已证实的设计缺陷**：

1. **规划第 5、7 行：明确 P1 的作用对象和合法网格。** DATA 应说明对提交节点值及输入目标节点值分别在相同三角形、相同点重建后比较；声明一阶三节点、非退化、无重叠且相容的三角形范围、节点覆盖及域内点要求。共边／顶点上的连续 P1 值应与任选相邻单元一致；定位容差或拒绝规则不能由私有配置暗中补充。
2. **规划第 5 行：明确时刻和误差判据。** “完整所有时刻”与“指定点”的结合应说明是在给定帧比较还是还允许时间插值；若只比给定帧，应直接声明。整场和稀疏检查均需写清每个被选标量满足 `abs(candidate-reference) <= 1e-10 m/s`，以及未观察分量仍必须满足结构／有限值要求。避免“每个检查绝对误差”被理解为另一个未定义的聚合范数。
3. **规划第 11 行：AND 反例应单独失败。** 至少验证第一个检查通过、第二个失败，以及反方向；完整性反例应在未被数值观察的分量／帧上也触发结构失败。用于检查重建的场应至少有一个跨单元非全局仿射变化，避免全局线性场掩盖错误单元选择。
4. **文档闭环：** 成题后更新第零章目录，并保留 0.1 的实际状态说明。题面承诺、数据就绪、私有 verifier 准备和实际容器／Agent benchmark 是不同证据；不得将本次设计结论外推为后两者已验证。
