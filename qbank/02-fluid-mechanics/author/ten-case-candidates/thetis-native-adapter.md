# Native Thetis staging for remaining shallow-water cases

The installed Firedrake image imports successfully but does not include Thetis. Official Thetis release source is pinned to commit 162c605079611dfce69b4d1182181a421116b141. Its shallowwater_eq.LinearDragTerm supplies the native -C*u velocity residual, a prospective match for the frozen linear momentum drag in smooth fully wet cases. This is a source/module finding, not completed physical equivalence or a reference result.

The first proposed adapter is 2.9.2 case08: exact frozen P1 initial depth and velocity, flat bed, drag_rate=.1, all impermeable slip walls, no rotation or viscosity, end time=.5. Native nonlinear transport, boundary treatment and output sampling still require case configuration. No custom PDE or friction law may be written, and no quadratic/Manning law may substitute for linear drag.

stage_native_thetis.py runs one isolated, one-core, 2 GiB dependency/download/import stage with a 30-minute cap. It preserves downloaded distributions and SHA256 evidence in Titan maintenance; it changes neither shared host Python nor the base image. A successful import is native_solver_imported_pending_case_adapter and does not count as case computation, reference, or validation. A failed stage is retained and never automatically retried. Next inspect its exact status and implement the finite native case adapter only after import succeeds.

Sources: https://github.com/thetisproject/thetis/blob/162c605079611dfce69b4d1182181a421116b141/thetis/shallowwater_eq.py and https://thetisproject.org/download.html . Live resource decision and exact follow-up are stored in Titan maintenance/native-thetis-adapter-handoff.json.

The isolated native import succeeded; all downloaded distribution SHA256 values are retained. The finite case08 adapter is now dispatched. It generates the frozen public mesh and P1 initial fields, maps those same node values into native CG1 by exact coordinate identity, and uses native nonlinear DG-DG shallow water with LinearDragTerm. The depth datum is h=1+eta with constant bathymetry=1; the physical bed remains zero. Native default land boundaries implement closed slip walls. No rotation or horizontal viscosity is enabled. Native Crank-Nicolson advances 1000 steps to .5 s, with observer-only exports at the four frozen times. Native DG fields are retained; point outputs use native L2 projection into CG1 at real public nodes, an approximate reconstruction. The runtime script configures existing Thetis equations and reads outputs; it implements no PDE/source term. Completion still requires the actual native run and resulting reference package.

Case08 friction decay completed all four requested frames as an unvalidated candidate. The next finite case is frozen 2.9.3 case08: bed=.3*P1 bump, h=1-bed, velocity=0 and drag=.1. Input checks establish h>=.7 and exactly constant initial free surface. Native bathymetry is represented as 1-P1_bed and initial elevation as h-bathymetry; the datum changes no physical bed/depth. Wetting/drying regularization is explicitly disabled; this all-wet case does not demonstrate dry-front handling. Original producer/runtime versions and completed outputs are preserved.

The pinned source's ExternalPressureGradientTerm and HUDivTerm explicitly use linear Riemann relations at dynamic boundaries. Equivalence to the frozen nonlinear exterior-state Riemann condition has not been established. Therefore the proposed reservoir-pulse adapter was not implemented through this path; it remains an ordinary pending adapter, not a newly held case. The closed wet-bed case was actually dispatched instead.
