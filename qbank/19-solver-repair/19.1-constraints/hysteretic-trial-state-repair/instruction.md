# 滞回材料试探状态恢复

本题要求修复真实 OpenSees 单轴材料实现中的试探状态问题。可信驱动创建 `HystereticMaterial` 或 `HystereticSMMaterial`，沿单向骨架提交加载历史，然后多次改变未提交试探应变、返回已提交应变附近、接受该状态、继续加载、显式回滚及重置。返回附近时可能遗留先前试探的应力、切线或内部状态，从而污染后续提交。

你须使这两个真实材料类在 [DATA.md](DATA.md) 定义的范围内满足同一状态协议，并保留正常加载、回滚和重置行为。输入输出通用格式见 [CONTRACT.md](../../../../docs/CONTRACT.md)。公开材料含固定基线的必要真实源码及许可证、驱动、构建声明、输入输出适配器和运行探针。驱动直接调用材料 API；试探应变不是结构求解的时间步。

提交目录只允许有两个普通文件：`HystereticMaterial.cpp`、`HystereticSMMaterial.cpp`，分别替换源码树 `SRC/material/uniaxial/` 中的同名文件。即使某个文件无需修改，也须提交。不得提交目录、链接、额外源文件或构建产物。保留现有公共接口和实际材料实现；不允许改驱动、协议、构建配置或其他源码，也不能以固定结果、算例识别或替代模型代替真实材料计算。

可信环境使用 GCC 14.2.0、C++17、CMake 和 Ninja，重新编译上述两个替换文件及必要依赖，调用公开驱动形成数值输出。源码包根目录对应 `/opt/opensees-source`；公开 `CMakeLists.txt` 中该路径可在本地改为解包位置进行调试。公开 `run_case.py` 是运行接口，使用 `--input problem.json --output result.h5`。单个输入可以包含多条相互独立的材料程序。

按输入文件分别计分；该文件全部输出满足对应容差才得分，最终分数是通过文件比例。应变采用绝对容差 1e-19；应力、切线模量、已提交累计功密度分别采用绝对容差 1e-6、1e-4、1e-8 Pa，三者相对容差均为 1e-10，接受条件为绝对误差不大于绝对容差加相对容差乘参考值绝对值。公开样例同样受检；没有只针对试探返回的独立加分。

运行资源为 4 个 CPU、4 GiB 内存。每次候选构建限时 120 秒；每个输入运行限时 20 秒。构建或运行失败不得分；缺失工具或可信基线自身无法运行属于基础设施错误，单独报告。正式输入与参考不提供给提交程序；驱动只传入本次材料参数及操作序列。
