# 题库设计哲学

题库评测 Agent 生产可复用求解器的能力。求解器应覆盖公开声明的问题族，并在提交冻结后处理多个未见算例。

## 1. 统一题库，明确题目描述与建模责任

题库统一按章、节、子节组织，不将给定 PDE 的求解与 CAE 分析划为两大类。各题根据评测目标明确描述方式及 Agent 的建模责任：

- 给定数学模型时，题面明确模型、初边值条件的表达和输入输出含义，Agent 实现覆盖该范围的求解程序。
- 通过物理描述和方法要求定义分析任务时，不以预先列明控制方程、本构和闭合模型为默认前提。Agent 完成未被题目固定的建模选择、合理假设、计算设置与求解。

题目可以明确维度、稳态／瞬态、介质性质、可压缩性，以及是否考虑能量、湍流等范围。具体模型是否指定取决于方法要求；模型选择可以成为考查内容。总体规划见 [design/README.md](design/README.md)。

## 2. 问题族由能力范围定义

一道题定义一类求解能力及其适用范围。具体几何、材料参数、初始状态、边界条件和载荷由算例提供。腔流、圆柱绕流、弯管等是具体问题或算例类别，不因几何名称而各自成为物理问题族。

支持范围必须明确且有测试覆盖；有限的特殊算例不能证明求解器具备更广泛的能力。

保留来源身份的固定问题兼容专题单独标明其固定定义与评价范围。此类题用于特定连续问题的求解和兼容回归，成绩单独报告，不能作为可变参数问题族的泛化证据；核心能力题仍遵循上述问题族目标。

## 3. 题目独立于算例来源

先规划题目，再寻找或制作算例。PDEBench、FOAMBench 等仅承担算例来源的角色；没有现成来源不影响题目成立，增加或更换来源也不改变题目定义。

来源身份、原始配置、转换与改编过程、参考方法及局限保存在算例或参考材料中。来源不作为题目名称或隐含的求解条件。

## 4. 分离题目、算例与生产任务

- **题目**定义问题族、输入输出、方法要求和评价标准。
- **算例**属于某道题，给出具体输入及独立评价依据。
- **生产任务**选择一道或多道题，要求 Agent 生产同一个求解器覆盖它们。

多题任务一次提供所选题目的公开材料，冻结同一提交后分别评测隐藏算例，保留逐题成绩及明确规则下的整体成绩。求解器可以共享核心、组合模块，或按输入自动选择模型、算法和后端；冻结后不得针对隐藏算例修改提交。

## 5. 协议统一，语义明确，信息可组合

通用协议统一数据结构与引用，物理语义约定统一概念，逐题声明支持的组合。维度、分析类型、材料、条件和观测要求应独立表达；物理含义不能只靠题目 ID、文件名或来源推断。

同一概念在不同题目中保持一致；不同压力定义、单位、采样方式、时间及统计含义必须显式区分。兼容不要求字段完全相同，正交不意味着任意组合都有效，必要依赖与相容性应检查。

## 6. 方法自由与评价目标一致

除题目明确要求外，不限制语言、软件、数值算法或内部离散。解析解和降阶方法只要满足整个公开契约，同样有效。

允许自主建模的 CAE 题，应按共同的物理量、工程目标和适用性评价；不得用某一隐藏模型的专有变量或单一模型参考，变相要求考生复现指定配置。

## 7. 用证据支持成绩与能力结论

隐藏测试应包含有物理或数学意义的变化，覆盖题目承诺的范围。结构合法、成功运行、低残差和守恒检查分别提供有限证据，不能替代结果正确性验证。

参考与容差应有可审查的依据，并区分数值误差、模型误差和观测不确定度。与来源软件结果一致不自动等于符合真实物理；结论不得超出实际验证范围。
