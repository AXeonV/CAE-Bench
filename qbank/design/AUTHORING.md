# Agent 章节出题工作流

本工作流将 [题库哲学](../PHILOSOPHY.md) 落到可重复的章节建设过程。目标是让 Agent 从现有规划出发，补齐目标所依赖的规划，再完成一批可阅读、可实现、可审阅的试题。每次调用处理指定章节或小节，可以补足其上级规划，但不实施无关章节。

具体的“问题 → 原因 → 修复 → 后续检查”见 [经验清单](AUTHORING-LESSONS.md)。出题前读取该清单，区分已纠正的错误与可复用的工程做法。

## 这次形成的经验

2.1 节的 [审阅记录](reviews/section-2.1-statements.md) 表明：题号与物理分类一致，只是起点；考生还需要完整的条件语义、材料状态、采样解释和评价目标。维护端可以复用模板和实现；考生侧每题必须自包含。第二章后续简化的 [独立审阅](reviews/chapter-02-simplification.md) 说明，集中维护不应转化为要求考生逐层查阅共享定义。

“算法自由”不能补足缺失的物理边界。压力出口的储槽压力、流体内部静压、牵引和速度梯度不是可以任意互换的描述。类似地，二维量的厚度约定、体黏度的定义、等温声速、初态与迭代初猜、节点与边界实体平均都可能改变答案。审阅必须检查不同合理解释是否会产生不同物理问题，不能只检查格式。

完整题面与验证完成是不同状态。题面可先于数据完成，但阈值、资源和参考的可信度需要后续证据；空目录、合法 JSON、成功运行、低残差或回归测试通过都不能替代这些证据。2.1 的 600 秒、4 CPU、4 GiB、1% 相对容差等是该版设计目标，不是以后各章的缺省参数。

## 启动时确定的范围

从用户要求和既有规划提取以下内容，写入本次维护记录即可，不要求新增机器配置文件：

| 项目 | 需要确定 |
|---|---|
| 目标 | 章／节编号、已有规划及其缺口，规划完成后形成逐题清单与稳定标识 |
| 阶段 | 仅规划、完成题面、数据与参考、评测发布；未要求数据时不进入数据阶段 |
| 交付 | 目标目录、共用材料、逐题文件、维护记录 |
| 约束 | 既有用户决定、协议版本、是否保留空数据目录、提交偏好 |
| 待决事项 | 与已有决定冲突，或无法从用户目标与题库原则合理判定的关键选择 |

已有明确决定直接沿用。缺少规划本身不是必须向用户提问的理由；先提出并保存具体方案。对符合既定原则的组织、拆题和初版范围选择，记录依据并自主推进；只有上述关键待决事项才请求用户澄清，同时推进不依赖该答案的工作。用户仅请求规划时，完成规划即可；用户请求出题时，补齐规划后继续完成题面，不默认逐级等待批准。

## 规划补全阶段

按总体章目录、章内各节、目标节逐题定义的顺序检查，补足缺失的最上层依赖，再逐层细化。已有清晰层级直接复用，不为统一格式重新设计整章，也不覆盖用户已经决定的范围或已发布题号。

| 现状 | Agent 应执行 |
|---|---|
| 目标节已有清晰逐题规划，如 2.2 | 核对并直接映射题目，不重复规划 |
| 章已规划、目标节仅有方向，如 2.3 | 沿章内边界细化该节，提出编号、能力和责任明确的逐题表 |
| 仅有章级目录、尚无章内规划，如第三章中的 3.1 | 先规划第三章各节及相邻边界，再细化 3.1 的逐题表 |
| 目标方向尚未归属某章 | 先依据总体目录明确归属；若需要调整已有章级划分，提出具体变更和影响，不默默重排 |

**章规划**应给出各节编号、名称、核心能力、与其他节／章的边界及需要后续细化的方向。它只需提供目标节合理归属的完整框架，不要求同时写出其他节的逐题清单或题面。

**节规划**应形成可直接用于出题的逐题表，至少包含编号／题名、物理及材料范围、维度、稳态／瞬态／统计目标、考生的模型与方法责任、共同观测目标、与相邻题目的区别及明确不覆盖的过程。必要的协议缺口和待校准指标单列，不能以缺少来源数据删掉题目。不要把所有属性机械展开成笛卡尔积，也不要用“常见模型”等模糊词代替支持范围。

例如细化 2.3 时，需要明确平均场、非定常平均场与统计量的区别，说明 RANS／URANS／尺度解析的方法责任及闭合模型选择自由；不能根据来源配置默认按 k–ε／k–ω 等模型拆题。细化 3.1 时，从第三章的章级能力与边界出发规划，不把 CFD 的分节轴、材料类型或输入字段移植到固体力学。

规划写入 `qbank/design/`，沿用已有章文件或合适的节文件，并更新总体目录及相互引用。在维护记录中区分沿用的用户决定、Agent 新提出的选择及未决项；对新拆分说明能力上的区别，不假称已经用户确认。需要外部事实支撑的领域细节另行查证，来源服务于范围核查，不决定题目目录。

完成后检查：题目能否仅由规划确定其能力与责任、是否重复或遗漏目标方向、是否与相邻题目冲突、是否保留不必要的隐含模型选择。若用户要求完成出题，继续下面的题面阶段；若仅要求规划，到此交付，不提前生成题面、数据或评测。

## 整章执行与续作

用户请求整章时，先盘点全部目标节，为每节形成有限、明确的逐题清单，统一检查交叉边界后再分批实施。已有完整题目保留，只在发现缺陷或共享协议变更时修订；已有稳定题号不重排。尚属方向的临时子节编号若需拆成多个题号，保留“原方向 → 最终题目”的映射，不能将方向编号机械视为已冻结题号，也不能无记录地覆盖它们。

在维护记录中建立逐节状态表：规划及逐题清单、题面文件、依赖协议及实现状态、静态检查、独立审阅及修订复核、数据阶段、未决项和下一步。可沿用 qbank/design/reviews 下一个章级记录，并链接各节详细审阅。记录实际完成证据，避免用待办勾选替代验证。

按协议依赖和章节顺序实施；同一共享机制先设计再由多题复用。分批提交仅包含本次任务修改，每批完成更新记录并继续下一批，不因一节完成就把整章任务结束。中断／新一轮续作时先核对记录、Git 状态与实际文件，从第一个尚未完成的依赖继续，不重复已完成工作。

后续节改变共享协议、Schema、SDK 或公共题面时，列出受影响的前序题目，补做必要回归与独立复核；旧审阅结论不能自动覆盖新文件。收尾检查全部目标节：规划项是否均有对应题目、是否有重复或遗漏、编号与链接是否一致、单位／采样／边界等共同语义是否冲突、每道题是否都有最终版本的审阅依据。

完成标准是用户指定范围内的规划、题面和必需协议均落实；不能用概述、TODO 或尚未实现的字段代替。数据暂缺不影响这三个部分的交付，但数据验证及正式评测仍另报。若确有无法解决的目标冲突或工具限制，记录具体影响并完成独立部分，不虚报整章完成。

## 题面阶段

### 1. 将规划映射为题目

逐题明确能力范围与区别，包括维度、稳态／瞬态／统计目标、材料、耦合过程及方法责任。检查是否遗漏或重复规划项；具体几何和来源不能代替问题族。多题共用一个求解器是生产任务组合，不据此合并各题的物理定义或成绩。

### 2. 根据题面设计 DATA，并反馈物理缺口

沿“物理对象 → 输入声明 → 条件与采样 → 观测 → 评价”的链条核查：

- 单位、坐标、压力／势的基准、力与通量方向、二维／降维积分约定。
- 材料状态与已固定响应；考生可选择的模型和必须遵守的材料信息。
- 每种边界与初态的完整含义、出现条件、组合约束，避免用来源软件专有名字代替。
- 数组实体、点值／平均／积分、空间重建、时间插值与统计区间。
- 不同实现可以共同输出、共同评价的物理观测。

每题 instruction.md 先明确任务目标、物理／材料范围、建模与方法责任、资源及评分，再调用 [caeoj-design-data](../../.agents/skills/caeoj-design-data/SKILL.md) 设计自包含 DATA.md。DATA 设计从题面建立参数、条件、采样及输出契约；发现物理欠定或矛盾时返回出题环节，提出具体方案并同步两份文件，不能在接口里暗加模型或缩小目标。

只有现有结构或工具不足时才拓展基础设施。先按[核心与扩展职责](CORE-AND-EXTENSIONS.md)判断归属：`src/caeoj/` 只拥有中性数据、校验、评分和扩展接口；共享物理能力在 `qbank/extensions/caeoj_ext/`，不可复用的公开运行规则按需在本题 `extension/`；共用维护与装配在 `src/caeoj_tools/`，数据和参考制作在本题 `author/`。领域按物理组织，不以章号或题号命名。普通新增题目不修改核心或发布脚本，通用表示／扩展接口确有缺口时才改核心。

确需扩展时同步必要的领域 Schema、校验器、公开辅助接口、兼容性与验证；CONTRACT 不累加题目专用细节。候选工具由维护装配一次交付，统一 `pip install .`、固定公共命令和 `caeoj.sdk` 基础入口；考生不挑选扩展、注册路径或处理版本冲突，详见[公开接口设计](PUBLIC-INTERFACE.md)。开发安装核心及 `qbank/extensions` 的独立 provider，不把 editable 环境当作公开包可用性证据。维护说明放 qbank/maintenance/protocols，仅作内部实现参考，不是考生契约。

### 3. 撰写公开材料

每题的题意与接口要求由本题 instruction.md、DATA.md 与通用 CONTRACT.md 完整定义；公开材料包另含样例和工具等文件。instruction.md 完整给任务、方法责任、资源和评分，DATA 完整给该题所有物理字段、条件、采样与观测。禁止要求读章节 COMMON、共享 DATA、维护方领域／评分规范、其他题或源码来补足规则。

维护端可复用模板、生成器和实现，交付时展开为逐题自包含文件，只保留适用分支。不能把整份领域规范机械贴入每题，再让考生筛选。若共用实现改变，逐题同步相关 DATA；不能只更新一份维护说明。发布器只带必要工具及考生材料，不带 qbank/maintenance。

公开材料应使考生确定：求什么、支持哪些输入、不支持哪些过程、哪些建模选择自由、如何读写、如何判分以及资源边界。CAE 题不默认罗列控制方程或固定闭合模型；给定材料响应、单位和观测定义仍须足够精确。资源及容差无校准证据时明确记为维护方设计目标，不把它们说成已验证事实；也不复制其他题的数值。

删除与实现任务无关的来源历史、开发安排、隐藏测试设计、参考算法、答案信息和针对某个 solver 的修补提示。公开格式片段须标明片段，不能伪装成可运行样例。examples、references、cases 是否补数据按用户范围决定；空目录可用 .gitkeep 保留。

### 4. 静态检查与独立考生审阅

先检查题目清单、文件、链接和 JSON 片段，人工核对元数据路径、单位、条件参数和数组轴。静态检查工具不能判断物理语义完整性。

再让独立 subagent 以考生身份只读审阅。可使用以下任务描述，并给出本次准确的公开文件列表：

> 你是实现本批题目求解器的考生。只根据本题 instruction.md、DATA.md 与通用 CONTRACT.md，判断能否确定任务并实现接口。不要读取章节共享文档、维护规范、作者实现、隐藏数据或参考答案来补足题意。找出会改变答案的歧义、矛盾、未声明要求、资源陷阱，以及障碍、误导、无关或不应出现的信息。逐项给出文件位置、影响和最小修订建议。区分具体缺陷与可选润色；不替作者选择算法。本次是否要求实际数据以任务范围为准。

可以与 DATA 设计技能合并一次独立联合审阅；记录最终文件及覆盖范围，不对未变化的内容重复审阅。主 Agent 逐条处理意见：修复有依据的缺陷；不采纳时记录理由。涉及共用语义时同步修改拥有该定义的规范及受影响题目。修订后让审阅者读取最终文件复核，不能把首轮意见列表当作最终通过。反复审阅仍有争议时保留未决项及影响，不无限循环，也不将其写成通过。

考生审阅与维护核查分工：考生只依靠三文件检查实现、歧义与无关信息；维护方对照最终契约、工具和配置，按风险选取独立合法／非法变体，检查文档允许的是否被拒绝、禁止的是否被接受。具体方法见 DATA 技能的[验证流程](../../.agents/skills/caeoj-design-data/references/workflow.md)。模板按能力选段并同步修订；审阅结论注明版本、覆盖、证据及未决项，“通过”不是无缺陷保证。不要求固定轮数或必须发现若干问题。

### 5. 留下可追踪的交付

维护记录保存于 qbank/design/reviews，实际输入清单等本地产物写 runs。至少记录：范围、公开文件、独立审阅是否执行、问题与处理、验证命令和结果、未完成证据。

检查最终 diff 与工作树，按用户偏好提交本次文件。题面阶段不调用需要实际样例的发布器，不把占位目录发成正式解题包。最终答复提供入口与审阅记录，并明确数据未生成、哪些参数尚待校准。

## 各阶段的完成标准

| 阶段 | 必需工作 | 可宣布的完成状态 |
|---|---|---|
| 规划 | 按依赖补齐章／节、逐题清单、能力边界与方法责任，标明新选择及未决项 | 目标所需规划完成；不等于题面完成 |
| 题面与契约 | 规划映射、instruction 与自包含 DATA 设计、必要工具支持、静态检查、独立联合审阅及修订复核 | 题面完成；数据与参考是否缺失另报 |
| 评测配置与适配 | 根据题面与 DATA 映射当前 judge 的策略、资源、汇总与错误分类，完成实际可执行的验证 | 配置／绑定／执行分别报告；暂定设置不等于校准 |
| 数据与参考 | 公开样例及隐藏输入、来源与改编记录、独立参考依据、收敛／误差验证、预算内基准求解、全部数据接口审计 | 已验证的数据覆盖范围；不能声称超出覆盖的通用能力 |
| 评测发布 | 冻结版本、题面与评分配置一致、真实公开材料完整打包、包内工具与路径验证、逐例判分及错误分类检查 | 可运行且可追踪的评测版本 |

这些阶段可以在一次明确授权的任务中连续完成，也可分开调用。配置设计可在数据建设前开展；没有实际字段绑定、参考或执行条件时，不能宣称完整评测可运行。出题任务包含必要的规划补全；补章规划不等于获得其他节题面实施授权。题面审阅通过不自动触发生成数据或发布，数据来源存在也不自动证明参考可信。

## Skill 职责

| 入口 | 负责 | 主要交付 |
|---|---|---|
| caeoj-author-section | 规划补全、问题族目标／范围／方法责任、资源与评分，协调完整出题 | 规划、instruction，以及调用 DATA 设计后完成的整套题目 |
| caeoj-design-data | 根据给定题面设计输入输出，反馈题面问题，仅按需扩展工具 | 自包含 DATA.md、必要的题面同步修订／工具与验证 |
| caeoj-configure-judge | 按题面与 DATA 补全评分／执行配置，适配并验证当前 judge | 实际配置、必要框架适配、加载／执行证据及未决状态 |
| caeoj-audit-data | 按三文件和全部实际输入输出核查一致性 | 审计记录、具体问题与授权范围内的修订 |

原 caeoj-extend-io 已改名并调整职责为 caeoj-design-data，不保留另一套并列拓展流程。

题面与 DATA 定义考生要求，评测配置是这些要求在当前框架中的执行形式。当前题库逐题提供显式 grading.json；judge-config.json 和 Harbor 覆盖文件按实际需要提供，执行设置可从共享模板继承或组装生成。具体消费点与当前后端约束由配置技能每次核对。用户要求评测配置、实际可运行或发布时，出题技能协调调用；仅题面任务仍止于题面和 DATA，不暗中扩大为数据建设或发布。

## 调用方式

仓库技能入口为 [caeoj-author-section](../../.agents/skills/caeoj-author-section/SKILL.md)。例如：

```text
使用 $caeoj-author-section，按第 2 章规划完成 2.2 节全部题面。
examples、references、cases 数据留待后补；完成独立考生视角审阅并修订。
```

只需要为已有题面设计契约时，可调用：

```text
使用 $caeoj-design-data 为指定 instruction.md 设计自包含 DATA.md。
现有协议足够时不拓展；发现题面问题先提出具体修订方案。
```
