# Agent 章节出题工作流

本工作流将 [题库哲学](../PHILOSOPHY.md) 落到可重复的章节建设过程。目标是让 Agent 从现有规划出发，补齐目标所依赖的规划，再完成一批可阅读、可实现、可审阅的试题。每次调用处理指定章节或小节，可以补足其上级规划，但不实施无关章节。

具体的“问题 → 原因 → 修复 → 后续检查”见 [经验清单](AUTHORING-LESSONS.md)。出题前读取该清单，区分已纠正的错误与可复用的工程做法。

## 这次形成的经验

2.1 节的 [审阅记录](reviews/section-2.1-statements.md) 表明：题号与物理分类一致，只是起点；考生还需要完整的条件语义、材料状态、采样解释和评价目标。共用要求应集中维护，各题只声明差异，否则相同概念容易出现多个版本。

“算法自由”不能补足缺失的物理边界。压力出口的储槽压力、流体内部静压、牵引和速度梯度不是可以任意互换的描述。类似地，二维量的厚度约定、体黏度的定义、等温声速、初态与迭代初猜、节点与边界实体平均都可能改变答案。审阅必须检查不同合理解释是否会产生不同物理问题，不能只检查格式。

完整题面与验证完成是不同状态。题面可先于数据完成，但阈值、资源和参考的可信度需要后续证据；空目录、合法 JSON、成功运行、低残差或回归测试通过都不能替代这些证据。2.1 的 600 秒、4 CPU、4 GiB、1% 相对容差等是该版设计目标，不是以后各章的缺省参数。

## 启动时确定的范围

从用户要求和既有规划提取以下内容，写入本次维护记录即可，不要求新增机器配置文件：

| 项目 | 需要确定 |
|---|---|
| 目标 | 章／节编号、已有规划及其缺口，规划完成后形成逐题清单与稳定标识 |
| 阶段 | 仅规划、完成题面、数据与参考、评测发布；未要求数据时不进入数据阶段 |
| 交付 | 目标目录、共用材料、逐题文件、维护记录 |
| 约束 | 既有用户决定、协议版本、是否保留空数据目录、提交偏好 |
| 待决事项 | 与已有决定冲突，或无法从用户目标与题库原则合理判定的关键选择 |

已有明确决定直接沿用。缺少规划本身不是必须向用户提问的理由；先提出并保存具体方案。对符合既定原则的组织、拆题和初版范围选择，记录依据并自主推进；只有上述关键待决事项才请求用户澄清，同时推进不依赖该答案的工作。用户仅请求规划时，完成规划即可；用户请求出题时，补齐规划后继续完成题面，不默认逐级等待批准。

## 规划补全阶段

按总体章目录、章内各节、目标节逐题定义的顺序检查，补足缺失的最上层依赖，再逐层细化。已有清晰层级直接复用，不为统一格式重新设计整章，也不覆盖用户已经决定的范围或已发布题号。

| 现状 | Agent 应执行 |
|---|---|
| 目标节已有清晰逐题规划，如 2.2 | 核对并直接映射题目，不重复规划 |
| 章已规划、目标节仅有方向，如 2.3 | 沿章内边界细化该节，提出编号、能力和责任明确的逐题表 |
| 仅有章级目录、尚无章内规划，如第三章中的 3.1 | 先规划第三章各节及相邻边界，再细化 3.1 的逐题表 |
| 目标方向尚未归属某章 | 先依据总体目录明确归属；若需要调整已有章级划分，提出具体变更和影响，不默默重排 |

**章规划**应给出各节编号、名称、核心能力、与其他节／章的边界及需要后续细化的方向。它只需提供目标节合理归属的完整框架，不要求同时写出其他节的逐题清单或题面。

**节规划**应形成可直接用于出题的逐题表，至少包含编号／题名、物理及材料范围、维度、稳态／瞬态／统计目标、考生的模型与方法责任、共同观测目标、与相邻题目的区别及明确不覆盖的过程。必要的协议缺口和待校准指标单列，不能以缺少来源数据删掉题目。不要把所有属性机械展开成笛卡尔积，也不要用“常见模型”等模糊词代替支持范围。

例如细化 2.3 时，需要明确平均场、非定常平均场与统计量的区别，说明 RANS／URANS／尺度解析的方法责任及闭合模型选择自由；不能根据来源配置默认按 k–ε／k–ω 等模型拆题。细化 3.1 时，从第三章的章级能力与边界出发规划，不把 CFD 的分节轴、材料类型或输入字段移植到固体力学。

规划写入 `qbank/design/`，沿用已有章文件或合适的节文件，并更新总体目录及相互引用。在维护记录中区分沿用的用户决定、Agent 新提出的选择及未决项；对新拆分说明能力上的区别，不假称已经用户确认。需要外部事实支撑的领域细节另行查证，来源服务于范围核查，不决定题目目录。

完成后检查：题目能否仅由规划确定其能力与责任、是否重复或遗漏目标方向、是否与相邻题目冲突、是否保留不必要的隐含模型选择。若用户要求完成出题，继续下面的题面阶段；若仅要求规划，到此交付，不提前生成题面、数据或评测。

## 题面阶段

### 1. 将规划映射为题目

逐题明确能力范围与区别，包括维度、稳态／瞬态／统计目标、材料、耦合过程及方法责任。检查是否遗漏或重复规划项；具体几何和来源不能代替问题族。多题共用一个求解器是生产任务组合，不据此合并各题的物理定义或成绩。

### 2. 检查协议是否足够表达题意

沿“物理对象 → 输入声明 → 条件与采样 → 观测 → 评价”的链条核查：

- 单位、坐标、压力／势的基准、力与通量方向、二维／降维积分约定。
- 材料状态与已固定响应；考生可选择的模型和必须遵守的材料信息。
- 每种边界与初态的完整含义、出现条件、组合约束，避免用来源软件专有名字代替。
- 数组实体、点值／平均／积分、空间重建、时间插值与统计区间。
- 不同实现可以共同输出、共同评价的物理观测。

若协议足够，引用已有规范；若缺语义，修订拥有该定义的共同规范；若缺结构或表示能力，再同步扩展基础设施并做相应验证。不要给通用 CONTRACT.md 累加某题专用细节，也不要只改文档而留下相互冲突的 Schema／工具。需要协议设计与实现时，使用 [caeoj-extend-io](../../.agents/skills/caeoj-extend-io/SKILL.md)，完成兼容性、实现及验证，再继续本节出题。

### 3. 撰写公开材料

建议节目录维护 COMMON.md、公共 DATA.md，题目子目录维护 instruction.md 和本题 DATA.md；已有合适布局优先复用。可共用的物理与 I/O 定义集中维护，逐题只声明选择和差异。引用文件必须随实际解题材料一起交付。

公开材料应使考生确定：求什么、支持哪些输入、不支持哪些过程、哪些建模选择自由、如何读写、如何判分以及资源边界。CAE 题不默认罗列控制方程或固定闭合模型；给定材料响应、单位和观测定义仍须足够精确。资源及容差无校准证据时明确记为维护方设计目标，不把它们说成已验证事实；也不复制其他题的数值。

删除与实现任务无关的来源历史、开发安排、隐藏测试设计、参考算法、答案信息和针对某个 solver 的修补提示。公开格式片段须标明片段，不能伪装成可运行样例。examples、references、cases 是否补数据按用户范围决定；空目录可用 .gitkeep 保留。

### 4. 静态检查与独立考生审阅

先检查题目清单、文件、链接和 JSON 片段，人工核对元数据路径、单位、条件参数和数组轴。静态检查工具不能判断物理语义完整性。

再让独立 subagent 以考生身份只读审阅。可使用以下任务描述，并给出本次准确的公开文件列表：

> 你是实现本批题目求解器的考生。只根据提供的公开题面、数据说明与协议，判断能否确定任务并实现接口。不要读取作者实现、维护记录、隐藏数据或参考答案来补足题意。找出会改变答案的歧义、矛盾、未声明要求、资源陷阱，以及障碍、误导、无关或不应出现的信息。逐项给出文件位置、影响和最小修订建议。区分具体缺陷与可选润色；不替作者选择算法。本次是否要求实际数据以任务范围为准。

主 Agent 逐条处理意见：修复有依据的缺陷；不采纳时记录理由。涉及共用语义时同步修改拥有该定义的规范及受影响题目。修订后让审阅者读取最终文件复核，不能把首轮意见列表当作最终通过。反复审阅仍有争议时保留未决项及影响，不无限循环，也不将其写成通过。

### 5. 留下可追踪的交付

维护记录保存于 qbank/design/reviews，实际输入清单等本地产物写 runs。至少记录：范围、公开文件、独立审阅是否执行、问题与处理、验证命令和结果、未完成证据。

检查最终 diff 与工作树，按用户偏好提交本次文件。题面阶段不调用需要实际样例的发布器，不把占位目录发成正式解题包。最终答复提供入口与审阅记录，并明确数据未生成、哪些参数尚待校准。

## 各阶段的完成标准

| 阶段 | 必需工作 | 可宣布的完成状态 |
|---|---|---|
| 规划 | 按依赖补齐章／节、逐题清单、能力边界与方法责任，标明新选择及未决项 | 目标所需规划完成；不等于题面完成 |
| 题面 | 规划映射、物理／接口契约、静态检查、独立考生审阅及修订复核 | 题面完成；数据与参考是否缺失另报 |
| 数据与参考 | 公开样例及隐藏输入、来源与改编记录、独立参考依据、收敛／误差验证、预算内基准求解、全部数据接口审计 | 已验证的数据覆盖范围；不能声称超出覆盖的通用能力 |
| 评测发布 | 冻结版本、题面与评分配置一致、真实公开材料完整打包、包内工具与路径验证、逐例判分及错误分类检查 | 可运行且可追踪的评测版本 |

这些阶段可以在一次明确授权的任务中连续完成，也可分开调用。出题任务包含必要的规划补全；补章规划不等于获得其他节题面实施授权。题面审阅通过不自动触发生成数据或发布，数据来源存在也不自动证明参考可信。

## 调用方式

仓库技能入口为 [caeoj-author-section](../../.agents/skills/caeoj-author-section/SKILL.md)。例如：

```text
使用 $caeoj-author-section，按第 2 章规划完成 2.2 节全部题面。
examples、references、cases 数据留待后补；完成独立考生视角审阅并修订。
```

规划不充分时仍使用同一个入口：

```text
使用 $caeoj-author-section 完成 2.3 节出题；现有方向不够清晰时先细化规划。
```

```text
使用 $caeoj-author-section 补充 3.1 节题面。
若第三章尚无章内规划，先规划第三章各节，再细化 3.1 并完成出题。
其他节只做章级规划，不撰写题面；数据留待后补。
```

这套自动化依赖 Agent 执行物理与语义判断，脚本只负责机械检查。无人审阅的批量文字生成不能替代完整的出题流程。
