# 题库数据存储设计

HF 采用**题内数据池**保存可复用的算例输入与参考。本地 `cases/`、`reference/`、`samples/` 是按选样清单下载并装配的结果，不再作为 HF 的权威布局。

第零章与第一章两道导热题已迁入数据池，逐题选样清单采用 `schema_version: 2`。历史镜像迁移及池迁移证据见[迁移记录](reviews/data-storage-migration.md)，现有 `caeoj-maint data` 上传、下载、选样、装配与核验命令见[操作指南](../maintenance/DATA-SYNC.md)。

## 存储职责

正式数据仓库为 [jimzhouzzy2006/CAE-Bench-OJ](https://huggingface.co/datasets/jimzhouzzy2006/CAE-Bench-OJ)，所有数据公开。按全库 TB 级考虑，获取单位可以是题目的选样集合、单个算例或样例及其依赖。

| 位置 | 管理内容 |
|---|---|
| 代码仓库 | 题面、DATA、协议、评分与执行配置、生成器、维护与审核记录；每题 `data-manifest.json` 保存稳定题目 ID、池定位和选样装配声明 |
| HF 题内数据池 | 算例输入与参考、逐项文件描述、池索引及本题共享数据，包括 `problem.json`、其他 JSON、网格、HDF5、CSV 和必要附件 |
| 本地装配目录 | 本次选样得到的 `cases/`、`reference/`、`samples/` 及必要的 `shared/`，由 Git 忽略 |
| 制作空间或另行安排的存储 | 来源下载包、转换缓存、中间结果、求解器检查点及可恢复的制作进度 |

按用途管理，不设大小阈值：属于算例的几行 JSON、小型 CSV 也放 HF。来源规则和审核结论由代码仓库维护；逐条来源身份和摘要随池条目保存，不把全量轨迹记录重复抄进代码仓库。

池中保存可直接消费的转换材料，不承担整个 PDEBench 原始库或制作过程归档。索引与选样清单不增加物理条件，不替代 DATA，也不扩展通用 CONTRACT。

## 路径与装配布局

HF 保留 `qbank/<章>/<节>/<题>/` 前缀，题内改用数据池。以下为职责示意，具体字段和索引分片格式在实现前确定。

```text
代码仓库：
qbank/<章>/<节>/<题>/
  instruction.md
  DATA.md
  data-manifest.json             # 题目身份、池定位、选样及装配声明

HF：
qbank/<章>/<节>/<题>/pool/
  index.json                     # 可选条目索引，规模扩大时可分片
  items/<case-id>/
    item.json                    # 来源、输入/参考状态、文件摘要、依赖
    input/problem.json
    input/…输入数据…
    reference/…参考数据…
  shared/…本题共享数据…

本地按选样装配后：
qbank/<章>/<节>/<题>/
  cases/<本地编号>/problem.json
  cases/<本地编号>/…输入数据…
  reference/<本地编号>/…对应参考…
  samples/<样例编号>/input/…
  samples/<样例编号>/output/…
  shared/…所选条目需要的共享数据…
```

HF 不为测试或样例角色重复保存同一条目。选样时赋予角色与本地编号，样例输出按现有契约装配为 `result.h5` 等所需名称。本地编号不是池内身份；更改选样或编号不要求重做转换。

章节或题目改名时，两边题目路径和定位声明同步迁移，稳定题目 ID 不变。共享先限于单题，不引入跨题依赖。

## 稳定身份

每题具有无章节含义、全库唯一的 ID，形式如 `caeoj-000123`，由本题代码仓库 `data-manifest.json` 的 `task_id` 唯一维护。示例不表示已分配。新编号分配前检查全库清单，自动分配机制另行设计。

文案修改、数据修复、增加算例、章节重排和路径迁移保留题目 ID；考查任务发生实质变化时创建新 ID。

池条目另有题内稳定的 `case-id`，独立于角色和本地编号。来源轨迹通过来源数据集、固定源文件身份及轨迹索引等追溯；自主生成数据也要有稳定条目身份。首批自主数据采用输入文件相对名称与摘要集合的 SHA-256 前 24 位加 `case-` 前缀识别，完整输入身份摘要保存在 `origin.input_identity_sha256`；输入不变时角色、编号及路径迁移不改变 ID。外部来源全轨迹的编号规则在实现时确定。

数据修复或重新编码可保留算例身份，但必须更新摘要。已有选样不能静默接受更新，需核对差异并显式更新绑定。相同标识不证明内容相同，不同标识也不证明输入不重复。

## 池索引、条目描述与选样清单

| 材料 | 负责的事实 |
|---|---|
| HF 池索引 | 可用 case ID、条目描述定位及筛选参数摘要；摘要从条目派生，不另作题意来源 |
| HF `item.json` | 逐条来源身份、转换绑定、输入/参考文件列表、大小、SHA-256、完整性与共享依赖 |
| 代码仓库 `data-manifest.json` | 本题 ID、池定位、明确选择的 case ID、测试/样例角色、本地编号及预期条目描述摘要 |

代码仓库不枚举全池数值文件。选样绑定条目描述的预期 SHA-256，再由条目中的摘要校验具体文件，避免两处独立维护同一份全池文件清单。不为存储目的向 `problem.json` 添加 HF 地址或数据版本。

可以按物理参数、尺寸、时间范围和完整性筛选，但正式选样必须落为明确的 ID 集合及绑定摘要。池增长、索引重排或重新执行筛选不能悄悄改变 benchmark。随机选择也要保存最终集合，不能只保存种子。

输入与参考分别声明完整性。输入已齐、参考待补的条目可供开发使用，不可正式判分。制作失败记录在制作进度中，不冒充完整条目。材料齐备、结构合法、来源审核、参考精度及资源校准分别记录，不能互相代替。

PDEBench 源输出不自动等于本题参考。全轨迹转换仍要应用对应模型的审核、修正或独立计算；不能为全量入池把未审核轨迹直接标为 reference。连续误差与评分校准证据仍由维护材料负责。

## 获取、装配与一致性

获取 case 默认包括输入、参考与共享依赖；样例也取得完整输入输出。参考待补时允许下载已有输入，但必须报告不完整。只取一个条目不要求下载整题或索引的全部分片。

装配取得所选依赖闭包。当前协议要求每个输入包自包含，因此共享数据通过文件描述的 `source` 指向题内 `pool/shared/`，装配时物化到各输入目录，保持 `problem.json` 的相对引用与字节内容不变。不得让输入向外引用本地题目共享目录；不改数组值、物理声明或参考含义。

样例包必须脱离维护仓库独立可用，不能漏掉网格、数组与共享文件，也不能递归复制整个池。按来源轨迹身份及输入内容检查样例与测试重叠，发现重复应报告并阻止将其作为独立测试，不能靠改名绕过。

| 状况 | 目标行为 |
|---|---|
| 所需文件不存在 | 获取并核对大小和 SHA-256 |
| 已有文件 SHA 相同 | 跳过下载或复制 |
| 已有文件 SHA 不同 | 提示差异，显式更新才覆盖 |
| 本地开发材料与选样绑定不一致 | warning，区分本地修改、池更新和材料缺失 |
| 正式 benchmark 材料不齐、摘要不符或依赖不闭合 | 停止，作为基础设施问题处理，不计考生失分 |

选样变化后，旧装配文件不能进入发布或判分。应先暂存并核验新集合，再替换工具管理的装配结果；不静默删除用户修改或未被管理的文件。装配回执保存本次选样、映射及实际摘要，作为本地运行证据，不成为第二份权威事实。

一次获取应解析到同一远端快照，避免索引、描述和数据来自不同更新阶段；具体机制待实现。仍只维护最新数据，不承诺长期保留历史文件或复现历史评测。摘要绑定用于拒绝不一致，不承诺历史数据可用，也不能证明符合题意。

## 公开访问与评测边界

全池公开不改变考生材料白名单：考生只获得题面、选中的完整样例、必要工具及既定公开评分材料。池索引、条目描述、整题选样清单、测试输入及非样例参考不进入考生包；评测材料按角色交给独立 verifier。具体要求见[公开接口与材料装配](PUBLIC-INTERFACE.md)。

隐藏/私有仅表示运行环境中的装配角色。网络策略由执行配置明确，本设计不推定现有环境已实现网络隔离。

## 当前格式与迁移

代码侧 `schema_version: 2` 清单的 `repository.path` 指向题目根，`pool.index` 为题内索引路径；`cases`、`samples` 按本地编号映射到 `case_id` 和 `item: {path, sha256}`。`samples` 可另用 `attachments` 指定条目内附件到样例内路径的映射。题目级 `auxiliary` 以路径和摘要绑定附件描述，保存必要维护附件的装配映射。

HF 池索引与条目描述分别使用各自的 `schema_version: 1`，与代码侧格式版本独立。索引的 `items` 定位条目描述并包含派生完整性摘要。条目 `files` 按逻辑输入/参考路径维护 `size_bytes`、`sha256`，可另有相对题目根的 `source` 指向本条目或 `pool/shared/` 文件。`input`、`reference` 各有 `complete` 和 `files`；`attachments` 声明附件。

`shared_dependencies` 是带 `path` 和 SHA-256 的描述绑定列表。依赖描述也使用版本 1，其 `files` 将逻辑输入/参考路径映射到共享 `source`、大小与摘要，可继续声明依赖；循环和目标冲突均拒绝。依赖合并后，分组的文件列表必须能找到全部逻辑路径。首批池没有依赖描述；新 `pack` 通过 `files.source` 自动去重。工具在读取时验证版本、路径、分组、摘要和冲突，未提供独立 JSON Schema 文件。

首批镜像数据已经整理为池条目，原测试和样例编号由选样声明还原，并逐文件比较原材料。远端旧 `cases/`、`reference/`、`samples/` 镜像在核验后移除，不再是下载入口。本地装配副本保留，不改写 Git 历史；不保留旧清单作为兼容消费入口，历史证据留在迁移记录。

迁移保留了原有样例与测试的重叠，并通过相同 case ID 明确表达，没有为满足新设计擅自重选已有题目。当前数据状态与原评测设计的限制分别记录；后续正式选样应按前述重叠规则处理，不能将迁移成功当作新评测已经就绪。

## 后续实施

通用制池、乐观并发上传与核验、按 ID 选择、依赖下载、事务装配、离线完整性检查及发布/Harbor 前置检查已接入维护 CLI。与来源转换无关的相同远端文件可跳过重传；这不等于制作过程已支持云端恢复。PDEBench 全轨迹枚举、转换进度远端恢复及独立机器 Schema 等仍待后续建设。

实施时同步生成器、忽略规则、发布/Harbor 装配、文档及 SKILL，并按真实消费链验证单条目与样例、共享依赖、部分就绪、远端变化、显式覆盖、旧装配清理、重复选样阻断、公开包独立可用与正式评测阻断。结构检查不代替数值正确性和资源验证。
