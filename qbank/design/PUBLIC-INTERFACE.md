# 考生侧公开接口与材料装配

日期：2026-10-16。状态：主要公开接口与装配路径已实施；具体证据、尚未验证的平台与运行范围见[重构记录](reviews/runtime-refactor.md)，实际描述字段见[维护说明](../maintenance/RUNTIME.md)。

本设计补充[核心与扩展职责](CORE-AND-EXTENSIONS.md)。维护侧可以拆分核心、共享扩展和题目扩展；考生拿到的是一套装配完成的工具。不能要求考生选择扩展、修复 import、修改 PYTHONPATH、寻找维护规范或解决题库依赖版本。

## 一、考生实际看到什么

| 材料 | 用途与阅读要求 |
|---|---|
| 本题 instruction.md、DATA.md、通用 CONTRACT.md | 唯一题意与数据规则阅读集合；资源、评分和方法责任不能藏在其他材料中 |
| 包根 README.md | 很短的操作入口：指向三文件、安装命令、真实样例路径和可直接运行的命令；不增加题意或要求理解内部架构 |
| 公开样例输入与输出 | 调试、结构校验与公开样例判分；不包含隐藏例或其参考 |
| 样例判分所需 grading.json | 工具输入；实际规则已在题面公开，不要求考生阅读策略树；GRADING.md 如保留只作同源可读展示 |
| 装配后的核心、必要扩展及资源 | 可选运行工具；提供源码便于检查，但不要求阅读、注册或改动这些文件 |
| MANIFEST.json 与已安装的装配描述 | 记录文件、核心／扩展版本和装配身份，支持工具自查；考生不编辑 |

维护仓库中的 `src/caeoj_tools/`、`src/utils/`、题目 author、qbank/maintenance、隐藏 cases 和私有 reference 不进入考生包。公开运行文件逐项列出，不能递归复制整个题目 extension 目录。若检查器需要一段代码，其依赖也必须完成公开性审查，不能因此带入参考求解器。

题面目录在公开包内保留既有 qbank 路径，输入中数据文件仍相对 problem.json 解析。根 README 生成具体路径；示意文档中的占位符不直接进入已发布使用说明。只有完整公开样例就绪才发布可运行包，不能把缺少输出的占位案例列成可判分样例。

## 二、统一安装：一个材料包、一次安装

从公开材料包根目录执行：

```sh
python -m pip install .
```

此命令是发布包的统一入口，不要求另装核心、领域扩展或题目扩展，也不使用 editable 安装作为默认。准备好的 Harbor 环境提前完成同等安装，考生开始后直接使用工具，无须再安装。

装配器生成公开包自己的安装元数据，将锁定的核心代码、选定扩展、题目公开运行适配和 Schema／注册资源一起安装。维护仓库的目录布局不直接决定考生包的安装布局；不要简单复制维护 pyproject.toml 后依赖文件碰巧可见。

- 装配结果作为一个 `cae-bench-oj` 安装发行包交付，保留 Python 导入名 `caeoj`；同时包含本次需要的独立扩展命名空间。核心可以另外独立安装，但核心版和装配版不以两个发行包同时写入同一 caeoj 路径。装配版本记录核心版本与装配身份。
- 扩展依赖在发布前求闭包、去重和检查冲突；第三方 Python 依赖按目标环境锁定。考生不输入 extras 列表、不逐个 pip 安装扩展、不运行注册脚本。
- 安装后的扩展描述和 Schema 使用包资源读取。换工作目录、将 problem.json 放到包外或使用绝对路径，都不影响加载；不依赖当前仓库、相邻题目或源码相对路径。
- Python 版本、OS／架构以及 Gmsh 等系统库的要求在材料入口写清，由环境制作负责满足。普通 pip 安装不等于自动安装系统库，也不等于跨平台或离线安装已经成立。
- Harbor 构建阶段准备所有依赖与系统库，独立 verifier 在禁网环境也能使用同一装配。需要离线安装的交付另提供与指定平台匹配的 wheel／依赖包并实际验证；不能只因 ZIP 带源码就声称可离线安装。
- 求解器使用的额外数值库与公开工具依赖分开：不会因为安装工具就强制使用指定求解方法，也不把参考制作依赖带给考生。

维护工具在包制作阶段完成构建与安装检查。任何缺模块、缺 Schema、依赖冲突或缺系统库都应阻止该平台发布，不能交给考生修补。

## 三、统一命令：保持当前三个主入口

公开 CLI 保留现有命令名与参数形式，`python -m caeoj` 与 `caeoj` 进入同一实现。README 统一优先展示前者，使命令明确使用当前 Python 环境。

以下是命令模板，发布器将其中样例和策略路径替换为真实路径：

```sh
python -m caeoj validate-input <sample>/input/problem.json
python -m caeoj validate-output --input <sample>/input/problem.json --output result.h5
python -m caeoj grade --input <sample>/input/problem.json --output result.h5 --reference <sample>/output/result.h5 --grading <task>/grading.json
```

考生不传 `--extension`、模型注册路径或章号。CLI 与 SDK 使用同一套已装配的契约描述，不能命令行检查完整而 SDK 仅检查通用 shape。输入的 task／model／profile 只用于匹配可信描述，不能作为任意模块导入路径。核心不硬编码题号或物理前缀；匹配规则由装配提供。

| 行为 | 约定 |
|---|---|
| validate-input | 检查通用结构和该题要求的已装配声明规则；通过不意味着物理适定、参考正确或可在预算内求解 |
| validate-output | 检查该输入要求的输出结构、引用、IDs／时间轴和声明约束；不检查数值答案准确性 |
| grade | 对明确给出的公开参考和策略评分；不自动寻找隐藏参考或执行求解器。正式示例始终显式传 --grading，不依赖旧默认容差 |
| 帮助与诊断 | `--help` 给出固定公共入口；`--version` 及 `info --input <problem.json>` 说明安装版本、装配身份、该输入的契约支持状态。它们不要求考生理解扩展实现 |
| 结果输出 | 三个主命令默认向 stdout 输出机器可读 JSON；日志不混入结果，错误有类别、字段路径和可执行的修正说明。缺扩展应提示材料包不完整，不提示考生自行注册 |
| 退出状态 | 目标统一为 0 成功／接受、1 输入或输出不符合契约／答案未通过、2 命令用法或工具／配置／参考等基础设施错误。须对当前分支差异做兼容验证后实施，不宣称已经统一 |

独立核心安装只能承诺通用结构检查，不能把缺少领域扩展后的结果呈现为题目契约通过。工具结果与 info 应明确检查范围；题目绑定要求的扩展缺失时必须失败，不能降级后返回完整通过。旧 PDE 中没有专属领域检查器的情况也要由可信装配显式声明支持范围，不能仅靠 model 未匹配而默认跳过。

make-cases、smoke、数据生成、发布、Harbor 组装等维护命令不出现在考生的通用 CLI 中。维护侧可有自己的入口，不让其可用性影响公开命令集合。

## 四、稳定 SDK：基础读写不随物理拆分改变

考生的默认 Python 入口保持 `caeoj.sdk`。现有通用函数的名称、参数、返回结构和数组含义保持兼容：

| 稳定入口 | 承诺 |
|---|---|
| load_problem(path) | 路径相对输入清单解析；自动使用已装配契约；返回含 manifest、arrays、meshes 的问题对象，不要求先注册或构造上下文 |
| load_result(problem, path) | 校验候选结果并返回数组，不把结构通过当数值正确 |
| read_constant(data)、read_option(data) | 读取声明值，不换单位、不猜缺省、不选物理模型 |
| read_field(problem, reference) | 接受逻辑字段引用，按声明解析实际 array key；保持 dtype、shape 和顺序 |
| target_ids(problem, location)、id_to_row(ids) | 提供声明 IDs 与行号对应关系，不把实体 tag 当作连续数组下标 |
| sample_field(problem, name, time) | 按明确的输入时间采样声明执行；不推断空间重建、外推或内部求解步长 |
| write_result(path, problem, fields) | fields 按输出 HDF5 array key 提供；保留既有自动复制 IDs／时间轴的便利，不自动改数值、单位或 dtype |

问题对象继续提供当前已被使用的通用数据结构，新增内部字段不迫使解题代码修改。公开的 `caeoj.validation` 校验入口、ContractError 及可读取的诊断报告也保留兼容；本次文档不重定义每个异常细节，迁移时以当前调用和测试逐项核对。

主安装路径不额外提供一个要求学习的 Session／Context 类。确有批处理需求时可以增加可选显式上下文，但默认 load_problem 和 CLI 路径必须完整可用，不能将其变成只做半套检查的快捷入口。

### 领域辅助函数的公开与稳定

材料关系、相质量、统计、周期条件等辅助实现留在物理扩展；它们不重新混回核心 sdk。公开使用路径与扩展内部文件布局分开：扩展提供少量稳定的物理能力入口，内部检查器与模块路径不作为公共 API。例如可在 `caeoj_ext.fluid` 的公开门面提供 dynamic_viscosity，而其实现位于 single_phase 或共享材料模块。具体门面清单在函数迁移时逐项确定，不自动公开所有内部函数。

已发布且在使用的 caeoj.sdk 领域函数及 caeoj.cfd／fluid_* 导入，在装配包中通过兼容适配保留原调用。适配由装配层生成／安装，不要求纯核心依赖所有物理扩展；不能把领域分派永久留回核心，也不能无说明地删除旧入口。适配只能转发同一语义，不能换公式、单位、压力基准或统计口径。

兼容别名由装配描述集中声明并检查重名：旧模块可交付薄转发模块，旧 SDK 名称通过通用别名机制委托给已选扩展；核心不逐个硬编码流体函数。未装配相应能力时明确报告不可用，不给出同名的近似实现。装配包内任何转发文件都由同一个安装发行包拥有，避免多个包覆盖核心文件。

新版推荐入口只在可选 SDK 使用帮助或函数 docstring 中介绍；DATA 仍独立给出数据含义，不能用“调用此函数即可”代替定义。迁移期不因换 import 而强迫已有 solver 重写；以后删除兼容入口需要明确版本、弃用记录与受影响题目核查。

工具不是求解要求。C++、Julia、Fortran 等程序可以按三文件契约直接读写，使用命令行做调试，不必导入 Python SDK 或与 SDK 产生字节完全相同的文件。

## 五、装配器替考生完成的工作

发布与后端共用一个装配结果，顺序为：

1. 读取可信题目绑定，选择核心与扩展版本，求依赖闭包；检查重复注册、版本／Schema 所有权冲突和循环依赖。
2. 收集公开代码、Schema、运行描述和第三方依赖，生成单次安装元数据。代码或 Schema 的重复来源不靠覆盖顺序解决。
3. 将运行绑定安装为包资源，由统一引导接口加载；考生不传配置路径。引导接口不枚举并执行任意第三方插件，也不执行输入文件指定的模块。确切注册格式在扩展接口设计中确定。
4. 收集公开三文件、真实样例及其判分策略，生成短 README；文件清单记录内容哈希，装配身份记录核心、扩展及绑定版本。公开身份不包含隐藏案例或参考的清单／哈希。
5. 从同一装配生成考生包与 verifier 运行材料，固定契约和评分实现版本。隐藏案例、私有参考和运行资源配置仅交 verifier；不以考生修改过的本地安装作为正式判分依据。
6. 在隔离安装环境运行下节检查，成功后原子替换发布产物；失败保留旧包。使用旧包或装配身份不一致时阻止后端组装，不沿用过期通过记录。

这套机制替代 publish_dist.py 的领域 TOOL_FILES 清单；目录层次与内部文件变动由扩展自身的受控发布描述承担。默认只装配本题所需依赖；是否提供更多可选辅助须明确决定，不能默认带入整个未来题库。

### 同一求解器覆盖多题

维护方一次选择有限题集，生成一个合并装配、一个安装入口和全部目标题材料。公共依赖去重，各题绑定独立保留；load_problem 按当前输入选择契约，不依赖上一题、当前工作目录或题目排列顺序。

不要求考生把两个单题 ZIP 覆盖解压后逐个 pip 安装；那样会造成同一命名空间覆盖与注册丢失。版本／声明不兼容由装配阶段解决或明确失败，不能以跨题合并为由暗改题意。命令和基础 SDK 与单题包相同。

## 六、必须通过的考生侧验收

以下为后续实施的验收要求，本轮文档检查不冒充已执行这些测试：

| 验收场景 | 应证明的结果 |
|---|---|
| 全新环境解压并执行一次普通安装 | 核心、所需扩展和 Schema 都可用；没有 editable checkout、仓库 PYTHONPATH 或维护目录依赖 |
| 移走源码／换工作目录后调用 CLI 与 SDK | 导入与包资源来自安装环境；输入清单及其相对资源仍正确解析 |
| 每类扩展的最小公开输入与输出 | 同一输入在 CLI、SDK、verifier 获得一致契约判断；不是只测 import |
| 缺扩展、未知绑定、版本冲突与畸形输入 | 工具／装配错误与输入错误区分；不会静默退回通用结构检查 |
| 当前解题代码与新版基础 SDK | 现有通用调用无需改动；旧领域入口兼容转发与新入口结果一致，独立手算值另作验证 |
| 公开样例判分及失败样例 | 使用明确的公开策略；结构错误、数值未通过、坏参考与工具错误分类可区分 |
| 多题合并装配 | 一次安装；同一进程交替读多题无状态串扰、无注册覆盖；依赖冲突在发布前发现 |
| 指定平台 Harbor 安装与禁网 verifier | 系统依赖已满足，运行时无需下载扩展或包；模型容器实跑与仅安装检查分别记状态 |
| 公开范围与材料入口 | 无私有数据／参考／维护代码；README 命令确实可执行，三文件足以确定题意 |

安装成功、校验通过和公开样例通过分别提供工具可用性证据，不证明隐藏数据完整、数值参考正确、一般求解能力或资源预算已校准。

## 七、迁移与后续边界

迁移前发布器复制固定 TOOL_FILES 和维护仓库 pyproject，README 推荐 editable 安装，领域辅助集中于 sdk，CLI 按 examples／smoke 是否存在显示维护命令。现已使用可信运行描述、按需扩展闭包、生成安装元数据、稳定基础 SDK 与领域兼容适配；README 给出真实样例命令，支持多题一次装配。

技能与公开入口已同步实际使用方式。多题公开包不等于多题联合 Harbor 调度；当前 prepare 仍逐题。依赖按构建环境锁定，新平台与新平台条件依赖仍须独立装配、安装及运行验证，不能泛化已有平台证据。参考精度、正式案例与预算校准保持独立状态。
