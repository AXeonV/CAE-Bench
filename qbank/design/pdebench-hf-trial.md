# PDEBench HF 云端迁移试验

## 范围与责任

用户要求从零设计迁移，来源限 HF 已发布的 25 个一维文件、250000 条轨迹，大数组不经过本地，累计 Jobs 计算费用不超过 USD 1。本次先覆盖每文件 10 条轨迹，独立保存来源诊断与可消费 case，不改变旧题、旧池或正式测试选择。

来源固定在 hf_source_probe.py 的三个仓库提交。第一阶段只检查与提取原始子集；通过结构检查不能记作数值认证。阶段二从清楚的数学问题开始，先建设周期线性输运题，其余两个族保留源子集和差异，未解决模型与参考语义前不冒充可判分案例。

## 首题能力设计

拟建 `linear-periodic-transport-1d`，归第 1 章 1.3 标量输运：在 [0,1] m 上求 ∂t u + b∂x u=0，周期条件，b∈{0.1,0.2,0.4,0.7,1,2,4,7} m/s。输入是 1024 个等长单元的分片常数初态，每个初值有限且绝对值不超过 1000。输出是全部原单元的积分平均值，时刻含 0、严格递增，0≤t≤2 s，1～201 帧。考生自由选择满足契约的解析或数值方法。

目标是处理参数、一般分片常数初态和采样时间的变化；来源替换不会改变 PDE 和观测定义。它不考查建模、逆问题、训练模型或仿真某个特定离散算法。本题与黏性 Burgers 的非线性与扩散机制不同；本次不以归档规模宣称更广范围覆盖。

参考使用文献中的周期平移公式 u(t,x)=u0(x−bt) 对原单元积分，实际输入数组就是完整初值。HF 原始初态和参数作为工况来源，归档后续帧仅作来源诊断，不将其直接称为新连续问题的精确解。公式出处为 PDEBench 论文 arXiv:2210.07182v2 附录 D.1；必须核对公式及独立积分检查。来源有限体积数值轨迹与新连续问题的关系单列，不通过宽松容差掩盖差异。

拟定逐点标准为 |误差|≤1e−6+1e−6|参考|，全部时刻和单元均需满足；此为明确精度目标，不从 Agent 成绩反调。参考先验证计算误差显著小于目标。试验阶段资源设为每例 120 秒、2 CPU、2048 MB、输出上限 16 MiB，需用真实消费核查，不能外推为所有输入的性能证明。

## 数据与发布边界

新题使用现行 CONTRACT、Gmsh/HDF5 和 data_pool 工具。来源记录保留固定仓库、文件 SHA、轨迹索引与载荷摘要。pool case ID 由输入摘要生成，参考与评分改动不生成新身份。新题试验 ID 必须检查现有身份唯一性。试验只上传新分支，默认选择为空，不发布 Agent benchmark。

80 条平流初态作为试验 case 候选；120 条 Burgers 和 50 条可压缩流子集仍属作者来源材料。初态索引分层只说明取样规则，不宣称物理独立或全面覆盖。全量分片池扩展不在未测通的首次试验中一次重写；小批使用现有自包含格式测通后，根据文件数量、读取和费用证据决定扩展。

## 预算与恢复

首个 CPU Upgrade Job 硬超时 3600 秒，按实时单价 0.0005 USD/分钟及额外一分钟预留 0.0305 USD。每次提交先写持久预算保留记录；未知提交结果不自动重试。所有本次 Job 的最坏计算预留累计不超过 USD 1。此数字是计算预算，不等同账户账单；计算与持久存储分别记录。所有数据获取和重读验证在 HF Jobs 内运行，本地仅接收代码、JSON 和日志。
