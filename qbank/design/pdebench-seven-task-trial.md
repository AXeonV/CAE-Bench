## 数量与公开身份

用户指定每题 20 条独立轨迹，全部作为 20 个计分 case，其中 2 个 case 同时制作公开 example，不增加独立轨迹。

- 7 题 × 20 = **140 条独立轨迹、140 个计分 case**。
- 7 题 × 2 = **14 个公开 example**，分别关联上述 140 个 case 中的 14 个。
- **126 个未公开 case，14 个公开且参与计分的 case**。逐题报告保留 20 例原分母，并另列 18 例未公开结果；不把公开题算作未见输入泛化证据。
- 采用现有[数据池公开 case 语义](DATA-STORAGE.md)：允许同一身份兼任测试和样例；测试内部仍禁止重复轨迹，不通过建立两个不同 case 身份放行重叠。

本次为独立的 20 例/题试评测选择，不覆盖题内既有正式选择，不宣称符合原题面所列正式评测集总例数。题面、DATA、物理范围和逐例评分不变。

## 时间、字段和 example

- 评测 case 每条最多 9 个真实输出帧，包括初帧和末有效帧，优先非均匀帧索引，避免平流所有采样都碰巧落在整周期平移时刻。
- 时刻取源实际时间轴，超出题目时间/空间/参数范围的来源拒绝；不足 9 帧时保留实际帧数，不插值或补造。
- 公开 example **完整复制其关联 case 的输入与输出时间轴**。其 output/result.h5 与同一 case 的 reference.h5 数值一致，并复制公开判分所需资产；不改成另一次选样、不裁掉部分帧。
- 9 帧 example 符合这些题目 1～9 请求时刻的题意，但当前工具对独立 sample 条目有最多 5 帧的内部限制。新方案从 case 引用生成 example，继承 case 帧，不通过修改题面或静默裁剪规避这个限制。
- 维持 float64、原空间网格及现有字段映射；FHN 不用粗网格初态代替完整细网格初态。reference 取对应源字段，不重新求解 PDE。

## 实施前必须补齐的工具能力

原先直接来源 selection 拒绝 sample/case 同源、非 HF 装配丢失公开身份；目前已补齐 schema_version=2 的显式 examples 引用与公开身份传递，当前操作见 [工具 README](../../src/utils/PDEBench/README.md)。本节保留所需验收目标；七题 140 条制数尚未启动。

1. selection 仍只登记每题 20 个唯一 case，另设公开映射，例如 `examples: {"01": {"case": "001"}, "02": {"case": "011"}}`。此为结构示例，最终映射随来源选择冻结，不预定这两个编号的来源配置。
2. example 引用同一 case 身份、来源、输入与参考摘要；生成样例副本不再重复读取源数据。已有独立 sample 入口是否保留按真实调用方决定，避免长期维护两套来源制作逻辑。
3. 复用通用公开 case 核验语义，将经过核验的对应关系交给既有 Harbor `tests/selection.json` 和 `public_sample` 报告链；不伪造 HF manifest/回执，不上传 HF。
4. 在发布/装配前严格核对输入、参考、时间轴及身份完全一致；样例内部、case 内部和非显式引用的轨迹重叠仍拒绝。
5. 回归覆盖：20 个计分 case + 2 个 example → total_cases=20、public_cases=2；任一映射被改动、裁帧或替换参考时拒绝；公开包只含选定的两个 example，不泄露其余 18 例。

## 空间与资源预算

估算沿用当前未压缩 HDF5、float64、ASCII 网格；20 个 case 均取 9 帧，两个 example 与其关联 case 完全重复。这里有意按实际目录复制计入空间，不预先假设硬链接、压缩或共享网格优化已经实现。

| 内容 | 预计磁盘空间 |
|---|---:|
| 平流、Burgers、吸附扩散三题合计 | 约 10～20 MB |
| 一维可压缩流 | 约 7～10 MB |
| 二维反应扩散 | 约 0.6 GB |
| 浅水 | 约 0.06～0.08 GB |
| 二维可压缩流（8 条 512²、12 条 128²） | 约 1.1～1.3 GB |
| **140 个 case + 14 个 example 的标准目录合计** | **约 1.8～2.2 GB** |

建议制数工作根与缓存合计预留 **8 GB**；同时保存公开 ZIP、Harbor 隐藏资产副本及装配暂存时，预留 **12～15 GB**。不含 Docker 镜像、其他历史运行和模型输出；一次模型评测全部 140 例的原始输出另估约 0.8～1.1 GB/尝试，失败/多次尝试按实际计。

七题最多涉及 37 个 catalog 文件，单源范围缓存上限 64 MiB，全部保留的范围缓存上界约 **2.5 GB**，已在预留中考虑。源 HDF5 压缩 chunk、元数据及重试决定实际下载量，不能用成品 2 GB 倒推出网络流量；先按下面的小批预检校准并冻结网络上限，不无上限下载或回退整文件。

512² 单条二维可压缩流的保守制数磁盘预检约 1 GB，实际复制/校验峰值与成品大小不同；顺序处理高维 case，不为提速同时堆多份高维暂存。

## 执行阶段与交付

1. 实现上述 case→example 引用与公开身份传递，先以本地 fixture 验证计数、身份、泄露边界和失配拒绝。
2. 七题逐题探测目标来源布局；优先给尚未实测的吸附、FHN、浅水、二维可压缩流各做少量真实消费，记录冷缓存下载字节、时间、磁盘峰值及已发现问题。已有三题只能复用匹配版本的验收范围，新增边界/配置仍需检查。
3. 冻结 140 条来源、原始帧和 14 个公开引用，按题/小批制作；高维每批 1～2 条，完整条目复用，不重下载已通过内容。
4. 对全批 140 个 case 与 14 个公开副本做字段/轴/条件/来源映射、参考/example、自判分正反例和重复身份审计；生成七份公开包及 Harbor 任务，逐题记录 20 例与 2 个公开身份。
5. 验证公开包独立安装、真实 trusted judge 消费；仅在数据全部通过后交付可启动模型评测的固定任务与命令。模型、次数与预算另按用户指定，不在制数规划中默认启动。

任一来源未通过，保留已完成量与明确缺口；不修改题面、用另一题替代或重新求解参考凑齐 140 条。三道暂缓题和三维题均不纳入此次运行，也不恢复旧 HF 迁移任务。
