# 首版题目目录与资产账本：P0工作规划

阶段：规划，尚未执行本计划的逐题资产审计或Titan连接。首版范围、题型和发布门槛由[发布规划](qbank-release-plan.md)拥有；本文件只规定P0盘点的对象、证据和交付。既有267题本地目录快照是起点，不是本账本已完成的证明。

后续本地题目／case盘点已形成[第一轮检查稿](release-task-case-review.md)，覆盖其他工作树及独立checkout的历史资产；七维资产审计和Titan实时检查尚未全部执行。该记录不回写为本规划当时已完成。

随后已完成第二章候选根目录及旧FOAMBench目录的有限Titan只读检查，证据见[第二章发行筛选检查稿](reviews/titan-inventory-2026-10-23/chapter02-release-review.md)。按后续用户决定，无case不纳入发行；其他资格审查仍需独立完成。

## 1. 范围与产出

逐题覆盖第0、1、2、19章共102个候选目录（2、13、65、22）。第3—18章保持开发资产，不纳入本次深入盘点。首版四章内可以暂缓个别题，暂缓理由必须可追溯。

P0交付一套关联账本及由其生成的阅读视图，回答每题“题目承诺什么、有什么资产、在哪里、证据有多新、还缺什么、下一步做什么”。不下载数据、不装配case、不重算、不构建镜像、不跑Agent、不更改远端任务。后续实施单独推进。

## 2. 账本结构与事实归属

复用现有task_id、case_id、数据manifest和证据，不另造第二套评分配置。采用题目、资产、关联三类记录；具体文件格式在实施时按现有工具选定，不先建设通用资产管理平台。

|记录|必要字段与职责|
|---|---|
|题目|稳定task_id、题目录、章与能力标签、当前／计划submission_kind、首版候选状态；关联题面、DATA（适用时）、评分配置及其版本；关联资产／审阅／缺口ID|
|资产|asset_id、类型、逻辑身份、来源版本、摘要及算法、字节量（已知时）、完整性、数值资格状态、许可证据、可见范围；通过locations记录一个或多个副本|
|资产位置|本地／Titan／HF等位置、路径或对象标识、observed_at、检查方式、存在／可读状态；未知大小或摘要明确留空，不推断|
|题目—资产关联|task_id、asset_id、case_id或批次、用途（输入／参考／原生复现／环境／验证等）、匹配依据、匹配状态、适用题目版本；多题共享资产不重复统计体积|
|审阅证据|review_id、类型、报告位置、审阅对象及摘要、结论、时间、适用接口／环境；旧限定文件接口证据不能直接认证新repo_patch接口|
|缺口|gap_id、对象、类别、已知事实及证据、影响、后续动作、阻塞的阶段、状态；记录待查、待补证、待修订、待验证，避免统一写成“缺数据”|

账本用链接引用题面、科学语义、配置和验收报告；不抄录可漂移的容差、资源预算或公式。本机／远端路径保存在维护账本，发行清单只引用稳定身份与可获取对象，不暴露为运行依赖。凭据、令牌和私钥不入账。

每项观察附时间与证据来源。事实未知记unknown；不能以空值代表不存在，以文件存在代表参考正确，以镜像存在代表可分发，以旧审阅通过代表当前材料通过。

## 3. 逐题关联内容

|维度|需要查清的内容|
|---|---|
|题面|instruction及适用DATA／CONTRACT、摘要、当前问题族与声明范围；已知歧义和修订需求|
|来源|原始数据／论文／issue／PR、真实源码及基线提交、生成器／转换器；来源与当前题意的匹配依据|
|输入与参考|本地正式目录、数据池／下载缓存、原始计算、转换产物、日志；批次／case映射、完整性和现有独立资格证据|
|环境|镜像tag与实际digest、源码／依赖锁定、离线材料、构建配方、已知平台与资源证据；仅盘点不构建|
|评分|当前判分入口、case选择与权重、参考／负对照记录、full／fast支持状态；区分当前能力与计划迁移|
|审阅|设计、考生、数据、运行验收记录及对象版本；标记未审、过期或只适用旧接口|
|许可|源码、依赖、数据和参考分别登记LICENSE／NOTICE／来源材料、目标分发范围；未确认项记待核实，不把仓库许可证自动套用给全部资产|
|缺口|不存在、未找到、未检查、版本不明、转换未完成、物理不匹配、精度未验证、环境不可迁移、许可待核实等分别记录|

以“本地完整可用／本地存在待核对／远端已证实本地缺少／仅历史记录／未定位”描述位置事实，以独立字段描述参考资格。P0只汇集已有数值证据，不开展新的数值验收。

## 4. 本地优先的盘点顺序

1. 从已有目录快照限定四章任务身份，核对当前目录、题面与现行manifest；明确第二章当前65题与历史63题之间的映射。
2. 查现有维护记录和已知数据根目录，再查正式cases、池／缓存、原始结果与日志；先轻量清单与已有manifest，不无边界遍历整盘或读取全部大场。
3. 先凭来源版本、case身份、现有摘要和文件清单建立关联；仅对待确认的小文件或必要对象补摘要。大对象未重新校验须标明证据层级。
4. 建立本地副本间的重复／冲突关系，不覆盖、移动、去重删除或重新下载。候选匹配不能自动变为正式case关联。
5. 本地足够的题明确记“无需HF补取”；只有具体对象缺失／损坏／版本不符才列补取需求。本地未知版本先核对，不默认重新拉取。

首轮不访问HF下载数据。已有HF提交可作为来源证据；如远端元数据核对确有必要，应在后续盘点中单列对象和理由，不触发全量同步。

## 5. Titan只读盘点方案（后续执行）

本轮只设计方案，不进行连接。实际盘点先复用既有连接配置及已知根目录，不新增远端服务或写入辅助脚本。

1. 区分旧FOAMBench、第二章十例候选及其他批次；读取各批manifest、状态摘要、产物清单、关键日志和时间戳，保存观察时间及远端身份。
2. 先读已有索引，再限定目录深度与文件类型列清单、大小、修改时间。避免递归读取全部大场、全盘hash或高负载命令；未深查的对象如实标记。
3. 对记录为running的批次核对实际PID、启动时间、命令、已运行时间和工作目录。PID不存在或复用分别标记，不能根据旧状态文件认定仍在计算；不启动、停止、重排或重试任务。
4. 将远端产物与本地副本按批次／case／版本关联，区分“本地已有”“远端独有”“可能重复待核对”“仍在生成”“失败／不匹配”。无稳定快照的运行中产物不认证为完整参考。
5. 只保存轻量观察证据到本地维护记录，不同步大数据。没有摘要时用源manifest／大小／时间建立待确认关联，不将其当作内容一致证明。
6. 输出需后续补取的最小对象清单、预计体积（可知时）及用途。若连接不可用，保留历史快照并标明live_remote_checked=false，不阻断本地账本整理。

远端盘点不执行安装、编译、求解、队列提交、容器变更、文件整理或清理；不读取无关用户目录和凭据。历史快照日期与当前观察时间分栏。

## 6. 工作分批与验收

先完成统一身份与证据规范，然后可按第0／1章、第2章、第19章并行只读调查；共享账本由协调者整合。Titan观察由单一执行者负责，避免重复扫描。数据审计、接口迁移与题面修订列入后续工作，不混入盘点。

P0完成条件：

- 102个候选题都有唯一记录，各项未知与不适用明确；孤立资产／未匹配批次单独列出，不强行归题。
- 每题七个维度（题面、来源、参考、环境、审阅、许可、缺口）均有证据链接或具体待查项；这只认证盘点覆盖，不认证可发布。
- 所有已登记资产的位置、版本证据和检查时间可追溯；本地可复用对象与后续补取对象分开。
- Titan实时观察已完成，或明确记录无法完成的原因和历史证据边界；63／65映射差异有逐项结果或待查项。
- 生成四章概览、逐题阅读视图、未归属资产表、补取需求及按阻塞阶段归类的缺口清单；各项数量由账本计算，不再手抄另一套进度。

P0结果用于决定首版选题和后续成本，不自动启动装配、下载或重算。原始盘点证据保留；发布规划发生调整时，旧审阅的适用版本应保持可识别。
