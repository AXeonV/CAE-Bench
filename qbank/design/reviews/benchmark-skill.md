# Benchmark 运行技能与本地监控

日期：2026-10-16。新增 caeoj-run-benchmark，负责题目就绪检查、冻结评测条件、材料组装、Harbor 运行、监控与结果汇总；不默认生成数据、修改判据或发布评测。本次仅创建和验证技能，未运行收费模型 trial。

## 实现与职责

SKILL.md 协调 audit-data、configure-judge，并把重复次数、并发、费用规模、补跑与重判、基础设施错误、参考校准边界和中断恢复写入执行要求。运行产物放 runs，计划与摘要不记录密钥；不自动上传 Harbor Hub、推送或更新 PR。

标准流程先启动真实 Harbor Viewer，固定默认端口8080，显式 jobs 模式，提供本机和执行主机本地IP URL。默认绑定0.0.0.0以支持本地网络接口访问，不把该绑定地址当浏览器URL；不自动配置公网转发或改防火墙。实际跨网段可达性与本机HTTP成功分别说明。

POSIX辅助脚本 viewer.py 维护 PID、进程身份、命令、日志与状态；只复用同一jobs目录和绑定，不结束无关服务或自动改变端口。ready 要求健康接口、正确jobs目录／模式及实际HTML页面，API-only不算成功。PID仍存在但身份不符记录为stale，不发送终止信号。Windows由技能要求使用原生等价进程管理，脚本不假称跨平台支持。

监控在正式benchmark结束后默认保留供回看，交付准确状态／停止命令。创建技能的临时服务测试则全部清理，不在用户默认8080留下测试服务。

## 依据与验证

- 核对实际安装 Harbor 0.24.0 的 --version、run/view/resume --help，以及 cli/view.py、viewer/server.py；Viewer默认127.0.0.1与8080–8089，技能显式固定8080，不沿用自动回落端口。
- 当前命令模板通过真实 `harbor run --print-config`，解析得到 attempts=3、concurrency=1、指定模型／adapter；该命令没有启动trial。
- 4项定向测试通过：启动／复用／停止、端口冲突不替换原服务、API-only失败清理、PID身份不符不误杀。
- 真实 Harbor 使用临时空jobs及随机回环端口完成启动、HTTP／HTML检查、复用、状态与停止；另验证通配绑定能返回本机及发现的本地IP URL。未占用默认8080。
- 独立 subagent 试用“明确模型的三次评测”和“数据缺失且端口冲突”两个请求，发现启动瞬间argv变化导致身份误判。已改为服务就绪后记录稳定身份，并复核真实CLI生命周期通过；不再返回成功却无法停止自己的服务。
- 新技能及修改的configure-judge技能结构校验、本地链接与diff检查通过。
