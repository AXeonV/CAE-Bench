# case 目录收束（2026-10-17）

## 结果与范围

HF 提交 [`e448a78086bab39c7ba4031509a6a40913527d27`](https://huggingface.co/datasets/jimzhouzzy2006/CAE-Bench-OJ/commit/e448a78086bab39c7ba4031509a6a40913527d27) 将首批三题改为 `pool/cases/<case-id>/`，每个目录只含 `case.json`、输入文件及可用的 `reference/reference.h5`。保留 68 个 case（smoke 11、稳态 33、瞬态 24），共 399 个池文件；仓库另有 README 和属性文件。

远端旧 `pool/items/`、attachments、shared 及附件描述被移除。新选择使用版本 3、`case` 描述绑定；case 描述和索引使用版本 2。工具明确拒绝旧格式，删除了共享解析、附件映射、题目级附属载荷和 `--no-auxiliary`，未添加兼容包装。

62 份原有 JSON 维护证据移入两道导热题的 `author/data-evidence/`，保留原字节，包括解析记录、catalog 和样例验证报告。旧的稳态样例额外 reference 副本属于重复数值材料，其消费答案已在 case 中保留，未将冗余 HDF5 提交到代码仓库。历史 HF 提交及本地迁移快照保留。

case ID、本地测试和样例编号不变。样例仍从 case 选取，既有样例/测试重叠未被偷偷重选；正式评测仍需处理这些重叠。数值输入和消费参考不变，smoke 仍明确缺少独立参考和公开样例。

## 工具与消费者

制池按 case 保存完整数据，不在不同 case 间去重网格。JSON 描述只列本 case 的逻辑文件、大小与摘要，禁止载荷 `source` 跳转及扩展附件字段。非消费记录进入 bundle 的独立 `evidence/`，不属于上传白名单；已有作者证据也可随 bundle 在本地收集。

两道导热题生成器改为直接把解析、catalog、验证记录写入 `author/data-evidence/`；对应数值测试改读作者记录。生成器不再为后续 pack 制造新的 HF 附件。旧来源准备工具的参考侧维护记录也会被 pack 分离，不会因为局部生成目录仍混有记录就把它们上传。

同步了数据管理、DATA 设计、实际数据审核和 benchmark skill；题意、核心协议、评分规则与资源配置未改变。

## 验证

迁移在上传前核对原消费文件摘要；从固定 HF 提交获取全部新池文件，逐文件比较本地 staged 大小及 SHA-256，再按新版清单装配到独立目录，核对所有所选输入与消费参考，并经真实 SDK 加载。随后更新本地清单和回执，清除原回执管理的维护侧文件；作者记录在清理前已另存核验。

完整回归 100 项测试、573 项子检查通过，覆盖制池/上传白名单、自包含装配、旧格式与共享跳转拒绝、证据隔离、摘要差异、覆盖与回滚、选样去重、公开包、Harbor、PDEBench 准备、运行时装配及稳态/瞬态数值测试。

实际重新生成了 32 个稳态算例和一个瞬态零解算例，验证作者记录的新输出位置；稳态混合样例不再留下重复 reference 副本。新生成稳态数据经通用制池与上传树校验通过。真实 HF 的相同 bundle 上传为 0 文件。两道导热公开材料合包及其独立运行时预检通过，包内无作者证据、池描述、选样清单或回执；四个相关 skill 格式及文档链接检查通过。不将上述结构或字节校验当作参考精度重新认证。

未执行全量 PDEBench 转换、云端计算或收费模型 benchmark。现行操作与字段以[存储设计](../DATA-STORAGE.md)和[操作指南](../../maintenance/DATA-SYNC.md)为准，早期记录仅保留历史证据。
