# 全来源成本校准范围

2026-10-18，用户要求实际测量并评估全部 250000 条迁移。沿用准备活动累计 USD .10 上限，并计入先前 readiness/migration-prep，亦受共享 USD 1 上限约束；不启动全量。

1. **全部来源层的 I/O。** 25 个固定文件，每个读取连续 0～127 和 5000～5127 两段，共 6400 条，全有效帧、全字段；检查有限值，写 float64+gzip HDF5，上传、固定提交重取、完整摘要及数值重读。分项计时与大小用于分文件外推。该阶段是来源搬运校准，不是正式 case，不能用其速度替代包装、SDK 装配和判分。
2. **当前正式 case 链。** Advection beta=7，原始行 2000～2999，共千例；使用既有契约、制数器、独立积分对照、正反例、pack/upload、固定提交重取和实际判分。与先前 beta=.1 千例比较实际流程改进及不同速度；每批属于实测，不自动授权其余批次。
3. **实际求解器重跑。** 固定 PDEBench 上游提交的现成数值内核，全部 12 个 Burgers 参数文件及 5 个 CNS 文件，每层读取既有子集首末两条（原行 0、9999），运行完整时间范围。CPU、float64，记录冷启动与预热；每层子进程 75 秒限制，包括导入、编译和三次双例运行，超时不能解释为“每条需要 75 秒”。同初态重复运行只用于计时，不算独立案例。
4. **高黏性替代与慢端。** 在预算预留允许后，额外测全部 Burgers 层的 Cole–Hopf 全时刻公式，64/128 模态比较；病态条件明确失败，浮点精度未认证。同时对 Nu=4 的一条轨迹实际运行完整上游求解器，最多 1200 秒；不是短时间段外推。

求解重跑使用出版配置的 CFL、gamma/pressure floor、边界闭合及 HF 标签参数作明确诊断；它们还不是经过审阅的新题物理合同。保留 epsilon/pi 的实际代码含义，归档初值作为数值初始场，不能把重跑吻合称为原连续初态认证。求解器源码直接在云端从固定 URL 获取并核 SHA，保留原许可头，不在本库或数据仓库再分发；数值软件署名 NEC Laboratories Europe GmbH。

main、正式选择和考生评测不变；数组不经过本机。报告与元数据才返回本地。计费观察、未结预留及未知取消状态分别列出，不将最大预留当实付，也不因取消接口缺结束时间就释放预算。


后续诊断调整：第一轮全时刻公式受默认 BLAS 线程开销影响，完成两层后主动停止，保留其报告。重测固定 BLAS/OpenMP/MKL 为一线程，不改变公式。另加 cns-focus 区分编译与求解：五层各单例完整时段，分别记录 JAX compile 和 first solve，每层 90 秒，Job 硬超时 600 秒、最大预留 USD .01；仍计入原准备活动上限。两例联合求解超时不能直接套成单例吞吐。

一次新增模式时的启动器分派错误误选公式诊断脚本，参数解析失败而退出；已修复为单一 worker_path 分派并定向检查，不作为性能样本。其运行费用照常计入。原千例 Job 曾在约 70 秒时主动取消，随后转独立发布分支；取消后服务端缺结束/时长字段，继续保留该次最大预留。默认线程公式取消也按同规则处理，不把取消当成免费。

增加 CPU Basic 实际千例对照，读取相同源文件和行段，以 API 返回的实际 flavor 为准。首轮虽然请求参数/账本为 Basic，但调用点仍硬编码 Upgrade；实际仍为 Upgrade，1000 例通过、Running=530 秒，不能作为 Basic 成绩。修复调用点后加入经过 main→run_uv_job 的无网络集成检查，重新在独立 v2 分支提交。错配这一轮按 API 实际 Upgrade 计费估算；它的最大预留 .00668 高于本次实际生命周期保守界 .0050，不释放其预留来掩盖错配。真正 Basic 的分钟单价由 API 捕获 167 microUSD（.000167 USD/min），30 分钟超时加 10 分钟启动余量预留 .00668；仍归原准备活动，不增加上限。

同输入重复上传可命中 Hub/Xet 后端的既有内容：两次 Upgrade 的 761/530 秒差异不能单纯归因为 CPU 或算法。因此硬件对照报告同时给首次/重复条件和相同 case 描述绑定，避免将缓存收益全归给低价硬件。Burgers/CNS 新参考的数值精度门槛及最终合同仍未确定，机械吞吐代理不改变这些未完成项。
