# PDEBench 全来源实测评估

当前预算与全量判断见 [BUDGET.md](BUDGET.md)。

2026-10-18。用户要求将先前的假设耗时换成实测。本轮在 HF 云端读取、计算和验证，未启动全量迁移、未改正式选择、未启动模型评测。范围和有界参数见 [PLAN.md](PLAN.md)。源文件固定为三仓库的 25 个文件、250000 条轨迹；这里的抽样行数不是独立初态数。

## 已闭合的传输与制池实测

| 测量 | 实际工作 | 结果 |
|---|---|---|
| 全 25 文件的来源流水线 | 每文件 0～127、5000～5127 两段，共 6400 行；全帧、全字段，float64+gzip 写入、上传、固定提交重取、摘要及数值重读 | 25/25 完成，约 11.48 GB 逻辑双精度数据、3.06 GB 压缩载荷；逐文件工作合计 411.82 秒，worker 含检查点约 432.1 秒 |
| 当前完整 case 链 | Advection beta=7，源行 2000～2999，1000 例；全 201 帧，1024 单元；独立积分对照、正反例、pack、分区池发布、远端装配、严格校验及实际判分 | 1000/1000，通过的参考与错误输出拒绝检查逐例执行；独立积分最大差 3.64e-12；CPU Upgrade Job Running=761 秒 |

25 文件来源流水线按每文件 10000/256 放大，约 4.47 Job 小时，USD .134。它测的是来源处理，不是完整 case：没有把 Burgers/CNS 归档重命名为合格标答。源 float32 数字转换成 float64 不补回原精度，转换后尾部零字节也易压缩；不能把这里的压缩率套到新计算的参考。

当前完整千例流程按 80000/1000 放大，平流约 16.91 Job 小时、USD .507；按 Running 分钟向上取整计算约 USD .52，不含额外 Starting。先前 beta=.1 的旧千例流程含其他固定开销，外推约 USD .64；二者不是同软件同工作量的统计重复，不能当置信区间。

若以已测来源流水线为底，再将当前千例完整链减去对应来源开销所得每例开销，按三族的存储输出量加权推广，250000 条约 57.35 Job 小时、USD 1.72；CPU Upgrade 工程规划可留 USD 2～3。这个总值仍包含外推：另两族的最终 case 合同、包装和判分尚未实测，不能称为“25 万个合格 case 全链已测”。公式和原始数字在 mechanical-assessment.json；它不额外叠加一遍全量来源费用。

## 真实数值重跑和公式成本

采用固定 PDEBench 提交的上游数值内核，完整源码在 HF Job 下载并核 SHA，原许可头保留，不随本仓库或数据仓库再分发。仅替换随机初始化与输出 driver；数值函数 AST 对照未变。旧 JAX `.loc` 改为 `.at` 索引 API，使用 JAX 0.4.38、CPU、双精度。原软件署名 NEC Laboratories Europe GmbH。代码身份及适配审计在 upstream-adapter-review.json。

12 个 Burgers 和 5 个 CNS 层各两条，源行 0、9999，完整时间范围；冷编译与重复计时分别记录。每层 75 秒包括子解释器导入、编译和三次双例调用，超时不能当作“每条至少 75 秒”。参考诊断的“completed”只表示诊断扫描已完成：17 层中仅 6 层完成全部求解及重复，另外 11 层被时间限制截断，不是 17 层参考全部通过。

Burgers Nu=.001/.002/.004/.01/.02/.04 六层，预热双例均摊约 .83/.84/1.66/2.48/4.95/9.28 秒/条。Nu=.1 首轮双例函数返回耗时 46.54 秒，之后重复未完成，也未走到最终数值结果检查；不能记为合格参考。已完成层与归档最大差约 3.4e-4～2.3e-3，可能涉及原初态、参数/生成设置和精度，不能单独判原数据错误，也不能冒充新题 1e-6 参考。

全时刻 Cole–Hopf 公式对 12 层各两条、全部 200 个正时刻实际求值，64/128 模态对照；首次默认线程试验的开销很大，已保留并中止。固定 BLAS/OpenMP/MKL 一线程后，128 模态通常约 1.3～1.45 秒/条，连同 64 模态对照约 2 秒/条。24 个参数–轨迹中 20 个可求值、4 个触发病态拒绝；低黏性即使可求值也可有明显模态差异，不能以“运行成功”认证。Nu≥.04 的 14 个样本均可求值，64/128 差异很小，但仍未认证浮点舍入误差和未抽中输入的适用率。

把低五层用已测上游数值求解、高七层用两次模态公式的实测时间组合，120000 条的**候选参考计算**代理约 USD 2.1（详见 burgers-route-assessment.json）；不包括低黏性分辨率验证、全样本失败率、浮点误差认证及包装。该数值只为选择路线服务，不能报成 12 万合格 case 的完工价。

最高黏性 Nu=4 还实际运行了一条完整上游求解（1024 单元、201 帧、t=0～2）：编译 .255 秒，求解 **585.55 秒**，结果有限，与归档最大差 .000539。按这一例速度外推该参数层一万条约 USD 48.82；这是单例速度外推，不是万条吞吐实测，也不代表优化后一维程序的性能。与同输入约 2.1 秒的两次模态公式相比，说明全量直接照搬显式参考求解不是合适的低成本路线。

CNS 首轮五层的双例 75 秒均未完成，随后每层单例、完整时间范围、单独计编译，90 秒窗口内仍均未完成；编译约 3.56～6.37 秒。导入/初始化和未完成求解的耗时没有被伪装成完整预热吞吐。故本轮没有得到 CNS 的完整单例求解时间上界或数值参考，不能将其成本填零、不能套“10 秒/例”，也不能据此得到可靠的全部可用 case 总价。

重跑采用出版配置中的 CFL、gamma=5/3、pressure floor、指定边界闭合及归档数字初态，仍不能证明它就是每条 HF 数据的历史生成设置。特别是 CNS 使用通用含三方向的实现、ny=nz=1；本次耗时不代表专门一维求解器或其他硬件的最优性能。当前结论是这条 CPU 重算路线未跑通，不能外推一份乐观总报价。

## 解释边界

- 6400 行覆盖所有参数文件和全时间字段，没有覆盖全部 250000 行的质量或困难尾部；固定两个连续行段不是随机统计样本。
- 单独 HF 下载目录避免文件缓存直接命中，但底层 Xet 块缓存/网络字节未仪表化；传输计时反映本次默认后端，不保证完全冷网络。
- 档案后续帧、求解器重跑与公式新初态解释分别保存，不互相冒充独立真值。source SHA 是固定上游身份，未独立重算完整 259 GB 归档的原始文件 SHA。
- 平流全部本批输入遵循题面/DATA/CONTRACT，并用 SDK 与实际判题链消费。其他两族本轮没有新题合同或正式 case，通过数值读取不代表合同及参考认证通过。
- HF 阶段之外，本机只接收代码、JSON 和日志；本轮不下载原始数组、TAR 或求解结果数组。先前两例容器载荷属于上一轮记录，不重复计为本轮下载。


## 实际两核对照与本轮费用

CPU Basic 最终千例 Running=502 秒，1000/1000 通过；实际硬件由 Jobs API 确认，runtime recipe 与首轮一致，1000 个 case 描述绑定全部一致，确认输入、参考和评分未变。重复八核完整运行 530 秒，仅作缓存/网络条件不同的重复；首轮八核 761 秒不能直接归因成硬件性能差。硬件代理与局限见 hardware-comparison.json，完整预算在 BUDGET.md。

本轮已知结束 Job 的完整生命周期加余量费用界合计 USD .03917，不是最终账单。两次取消的服务器响应没有结束/时长数据，仍各保留 .02；还有一次硬件请求错配按原最大预留保留。于是本轮预算占用 .08085，连同之前 readiness 的 .0055，同一准备活动累计 .08635，低于用户 .10 上限。不能将其中 .04 未结预留说成实际扣费。历次所有已登记 Job 的已知生命周期界 .06467、含未结预留的总账占用 .10635，继续低于此前 USD 1 累计上限。

初次辅助试验错误分派公式 worker，参数解析失败；初次拟两核运行未透传 hardware，实际为八核。两处均已修复、费用保留，并用无网络 main→Jobs 集成检查覆盖实际 worker/硬件提交；提交后还核对 API 实际 flavor，错配立即取消并保留预留。本轮定向检查 16 项通过，未重跑整套仓库测试；未用这些软件检查替代云端实际数据验收。
