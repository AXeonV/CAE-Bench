日期：2026-10-16。核心／维护发行版本：0.3.0；独立开发 provider：0.1.0。范围为架构迁移、公开接口与相关技能，不新增题目或正式案例，不运行模型评测。

## 完成内容

核心保留通用结构、数组、对象、诊断、几何原语、基础 SDK、评分和可信 runtime。CFD 与三个 fluid 模块迁出核心，按八个物理能力组织于 qbank/extensions；不再按章节编号路由。旧协议标识保留，原 reduced 模型记录中的 section 移除。

任务定位、题目配置读取、依赖锁定与装配进入 caeoj_tools；smoke 生成及执行移至本题 author。公开 CLI 不再根据源码是否存在暴露维护命令。基础 SDK 调用保持兼容，领域辅助与旧模块由安装描述转发到扩展；旧 SDK 的 params=、mass= 和两类周期配对签名分别保留。

发布器不再列举领域 TOOL_FILES，依据核心公开清单及扩展白名单求闭包，生成严格绑定、安装元数据和包资源。校验器与 SDK 自动使用同一描述。公开包一次普通安装，README 使用真实样例路径；多题可重复 --task 合并安装，各题交替读取不依赖当前目录或上一题。Harbor 的 prepare 仍逐题，未新增多题联合调度。

写入 ZIP 前，发布器另在隔离子进程从暂存的公开闭包加载实际 provider，核对所有公开样例、结果及评分绑定。该检查能发现开发 provider 未覆盖的题目专用钩子或严格绑定错误；它不代替普通安装与平台运行验证。缺失题目检查入口的定向回归已通过。

Schema 拆分保持未知键检查，显式处理核心扩展点与 peer 所有权，拒绝静默覆盖和畸形 Schema；JSON 重复注册、缺依赖、版本不符、循环、链接和越界路径在发布前失败。扩展 Python 依赖与核心依赖合并，按构建环境校验 markers、extras、Python 和版本要求，并精确锁定传递闭包。新平台条件依赖仍须在目标环境重新装配验证。

题面、DATA、通用 CONTRACT、正式数据与评分配置未变。结构合法不意味着物理适定或参考准确，原有数据与预算校准缺口未被本次迁移补齐。旧日期审阅散列保持为历史记录。

## 独立审阅与修订

独立 reviewer 只读审查核心、装配、公开隔离及兼容性，另有领域迁移与维护工具实施分工。审阅发现并闭合：畸形根 JSON／task 类型导致异常、未知模型漏检、SDK 关键字不兼容、Schema 顺序覆盖、纯核心检查范围不明、严格题目绑定缺声明仍跳过检查，以及前缀选择器的两处分支不一致。公开 README 的占位路径也改为实际样例。

最终审阅未发现阻断问题。审阅者独立执行 runtime 边界5项及六种能力闭包检查通过；文档未改变，因此未重新做考生题意审阅，代码审查也不冒充题目物理验证。
